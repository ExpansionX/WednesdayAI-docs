# MentraOS Glasses

`apps/mentra-glass` in [ExpansionX/WednesdayAI-apps](https://github.com/ExpansionX/WednesdayAI-apps/tree/main/apps/mentra-glass)
is a background miniapp (`com.expansionx.wednesdayai.glass`) for MentraOS display glasses
(Even G1/G2, Vuzix, Mentra display). It listens for the wake word, sends the spoken question
to your gateway, and streams the reply onto the glasses display. It runs as a background
miniapp, so other miniapps keep working while a reply is on screen.

## Support snapshot

- Role: gateway client app (`openclaw-mentra-node`), operator role. It is not a node and
  does not use `node.pair.*` pairing.
- Gateway required: yes.
- Install: sideload only. In the Mentra App, open Settings → Miniapp Developer Settings →
  Scan Miniapp QR Code and scan the QR printed by `bun run dev` in the app repo. For a
  standalone install, `bun run release` prints a `miniapp://release` QR.
- Transport: the app connects with `wss://` URLs, and with plain `ws://` only for
  localhost, loopback or Tailscale addresses (`100.64.0.0/10`). The glasses need a network
  path to the gateway.

## Pairing

1. On the gateway host, print a setup code:

   ```bash
   openclaw qr --client openclaw-mentra-node
   ```

2. In the WednesdayAI miniapp on the phone, tap **Scan setup QR** (or paste the setup code).
3. The first connect redeems the setup code and approves the pairing silently, so there is
   no `openclaw devices approve` step. The miniapp status shows the gateway host once it is
   connected.

The setup code is single-use and expires. Reconnects do not need it: the gateway mints an
operator device token at first connect and the app reuses that token. If the device was
removed or pairing must be redone, generate a fresh setup code.

## Wake word

The glasses trigger on the gateway voice wake config. Set it with:

```bash
openclaw gateway call voicewake.set --params '{"triggers":["wednesday"]}'
```

The miniapp reads the triggers at connect and follows `voicewake.changed` live. See
[Voice wake](/nodes/voicewake).

## What the client may do

The setup code stores a bounded profile for `openclaw-mentra-node`: role `operator`, scopes
`operator.read` + `operator.write`. That admits chat sends and history, session reads,
`agents.list`, and the voice wake get/set methods.

It never gets:

- the `node` role (no node invoke, no node pairing)
- `operator.admin`
- `operator.approvals`
- `operator.pairing` (device management)
- `operator.talk.secrets`

A connect that declares a scope outside the stored profile is refused
(`AUTH_DEVICE_TOKEN_MISMATCH` with `deviceTokenReason: "scope-mismatch"`), and a setup code
issued for a different client id cannot be redeemed by the glasses
(`bootstrap_profile_violation`). Full rules: [Gateway protocol](/gateway/protocol#client-identity).

## Device management

```bash
openclaw devices list --json                              # platform "mentraos", deviceFamily "glasses"
openclaw devices revoke --device <deviceId> --role operator
openclaw devices remove <deviceId>
```

After `remove`, the glasses must scan a new setup code to pair again. See
[devices](/cli/devices) and [qr](/cli/qr).

## Notes and limits

- Replies are display only. Stop the Mentra AI miniapp in the Mentra App so only one
  assistant answers.
- The device token and the glasses device key are stored in the miniapp session storage on
  the phone, not in the platform keystore. This is tracked as a finding in the app repo.
