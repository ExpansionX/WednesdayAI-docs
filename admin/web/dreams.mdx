# Dreams view

The **Dreams** tab in the [Control UI](/web/control-ui) (route `/dreams`, in the agent group
next to Learning) shows what the background task passes did: recent runs with their measured
cost and phase timings, the [Dream Cycle](/plugins/dream-cycle) state, and the health of
[Learning Core](/plugins/learning-core) lessons and skills. It is read-only: every panel needs
only the `operator.read` scope, and nothing on the tab changes Gateway state.

The data comes from the durable task run store through `tasks.status` and `tasks.runEvents`
(see [Task operations](/gateway/tasks)), from `dream.status`, `dream.weights`, and
`dream.candidates`, and from `learning.overview`.

## Panels

### Recent task-pass runs

A table of the 50 newest task-pass runs: task, status, start time, duration, a measurement
label, and model cost. Above it, the **budget window** shows admission units used in the current
window against the cap, the window length and start, the monthly ceiling, and the number of
budget denials among the runs in view. These are governor admission units, not model spend.

The measurement label says what can be shown for a run:

| Label               | Meaning                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| measured            | The run has a complete `pass.metrics` row.                                                              |
| measurement missing | The run finished without a complete row (for example a crash, or a pass that ignored its abort signal). |
| pruned              | The run's events are older than the retention period (30 days) and were deleted.                        |
| not run (denied)    | A budget gate deferred the run before it started.                                                       |
| in progress         | The run has not finished.                                                                               |
| events not loaded   | The `tasks.runEvents` call failed, so there is nothing to show.                                         |

A **dry-run** chip marks dry runs. Cost shows `$` with four decimals, `unpriced` when a model has
no config entry, and a dash when there is no cost to show.

Select a row to open the **run detail** drawer:

- **Lifecycle:** status, attempts, start and end times, trigger source, preemption count, the
  preemption reason (lease lost, reclaimed, or shutdown), the budget denial (budget window,
  monthly ceiling, or restart-loop guard, with scope and usage against cap), a "finalized on
  lease reclaim" note for a run recovered after a crash, and the last error.
- **Phase latency:** a waterfall of the run's `pass.phase` rows, each bar placed at its offset
  and colored by status (ok, error, aborted).
- **Tokens:** input, output, cache read, cache write, reasoning, and total. When usage was lost
  mid-run, the tokens known before that are shown instead.
- **Model cost:** cost in USD (a lower bound when some usage was lost), `costSource`, model
  calls, calls without usage, elapsed time, quality score, authoring path, and skip reason, plus
  "stopped early" and "selection truncated" flags when set.
- **Items:** the pass-specific counters from `pass.metrics.items`.

A dry run says so in the drawer: it made no model calls and no writes, and its counts are a
preview. A pruned run and a run whose measurement is missing are labeled rather than shown as
zeros.

### Dream state

From `dream.status`, `dream.weights`, and `dream.candidates`: whether dreaming is enabled, the
current stage of the newest active cycle, the crystallisation candidate and queued question
counts (shown as `≥ n` when the count is a lower bound), a table of active cycles (cycle, stage,
pending passes, failed stages, created), the configured stages with their last completion, the
per-agent adaptation weights (success rate, completed and failed totals), and the 20 most recent
candidates.

### Lessons and skills health

- **Counts:** active lessons, pending proposals, and applied proposals from `learning.overview`
  (shown as `≥ n` when the backend scan was truncated).
- **Consolidation quality trend:** a sparkline of `qualityScore` over recent consolidation runs.
  It merges the newest `learning-core.produce` runs whose metrics name consolidation as the
  producer with standalone `learning-core.consolidation` runs, and skips dry runs. Runs with no
  measurement (for example a crash-recovered run) cannot be classified and are counted separately.
- **Preemption share:** consolidation runs preempted (lease, reclaim, or ceiling) out of the
  consolidation runs in view. Shutdown preemptions are not counted as preempted.
- **Skill distillation:** the authoring path of the newest normal-mode distill run that recorded
  one. Dry runs, budget-deferred runs, and pruned runs are skipped.
- **Open Learning** switches to the [Learning](/plugins/learning-core#reviewing-what-was-learned)
  tab.

## Availability

Each panel loads on its own, so one missing plugin or failing store never blanks the tab:

- **Disabled:** the method the panel needs is not listed in the Gateway's
  `hello.features.methods`, which means the plugin that serves it is not loaded (for example
  Dream Cycle or Learning Core is off). Enable the plugin to fill the panel.
- **Degraded:** the panel could not load its data. This is often temporary — wait a moment and
  use **Refresh**. If it keeps failing, the panel shows the error: search the gateway logs for it.
- **Empty:** the call succeeded with no data, for example no runs yet.

Against an older Gateway that does not advertise its method list, panels try the call and show
degraded on failure.

## Refresh

- The Gateway sends a payload-free `dreams.update` event after a task outcome commits or a dream
  diagnostic fires. While the tab is visible, the first event refreshes at once and a burst of
  events is coalesced into one more refresh 1 s after the last event (at most 5 s after the
  first).
- While the tab is visible, it also polls every 30 seconds in case an event was dropped.
- While the tab is hidden (another tab is selected, or the browser tab is in the background),
  events only mark it dirty. It refreshes once when you come back.
- **Refresh** reloads every panel on demand. Opening the tab always loads it.

## Cost and pricing

Model cost is computed by the Gateway from the model entries under `models.providers`, not by
the UI or the plugins:

- A model declared under `models.providers` **without** a `cost` block defaults to zero cost.
  Its runs show `costSource: priced` and `$0.0000`.
- Only a model with no config entry shows `unpriced`.
- Set `cost` (`input`, `output`, `cacheRead`, `cacheWrite`) on a model to see real spend.

The budget window counts governor admission units, never model spend. See
[Run measurement](/gateway/tasks#run-measurement) for every `costSource` value.
