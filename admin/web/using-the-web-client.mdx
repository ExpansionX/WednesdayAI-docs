# Using the web client

The web client is a page you open in your browser to chat with your WednesdayAI assistant. You
can send messages, find and organize past conversations, choose how replies are displayed, and
check on things your assistant is currently working on.

The person who manages WednesdayAI decides whether this page exists and sends you its address. If
you do not have a link, ask them for one.

## Before you begin

- The web address for the web client, from the person who manages WednesdayAI.
- A **setup code**: a block of text that lets this browser start talking to your assistant. The
  person who manages WednesdayAI creates one for you. Setup codes expire, so use it soon after you
  get it.

## Pair this browser

The first time you open the web client on a browser or device, it asks you to pair - a one-time
step that links this browser to your assistant so it can be recognized on later visits.

<Steps>

<Step title="Open the web client">
Open the web address you were given.

You should see **Pair this browser with [your assistant's name]**.
</Step>

<Step title="Enter your setup code">
Paste the setup code into the **Setup code** box. The box should contain your code.
</Step>

<Step title="Pair this browser">
Select **Pair this browser**.

The button reads **Pairing...** briefly, then you land in the chat screen. If you see an error
instead, the setup code may have expired or already been used - ask for a new one.
</Step>

</Steps>

You only need to pair once per browser. Pairing this browser does not affect any other browser or
device already paired with your assistant.

## Install the web client on your home screen

The web client can be installed like an app: it gets its own icon on your device's home screen
and opens in its own window, without the browser's address bar.

<Steps>

<Step title="Open the web client in your browser">
Use the same address you normally use, and pair if this browser has not been paired yet.
</Step>

<Step title="Install it">
In Safari on iPhone or iPad, open the **Share** menu and choose **Add to Home Screen**. In Chrome
on Android, open the browser menu and choose **Install app** (or **Add to Home screen**).

You should see a WednesdayAI icon on your home screen.
</Step>

<Step title="Open the installed app and pair once more">
Open WednesdayAI from the home screen. An installed app on iPhone or iPad keeps its stored data
separate from Safari, so it asks you to pair again the first time - paste a setup code as before.

The installed app then remembers the pairing, the way a browser does.
</Step>

</Steps>

Two things the installed app does not do: there is no offline mode - it still needs a connection
to your assistant - and it does not show notifications while it is closed.

## Send a message

Type in the message box and press Enter (or select the send arrow). Press Shift+Enter to add a
new line without sending. On a phone or tablet, Enter always adds a new line instead of sending:
tap the send arrow to send. With a keyboard attached, Ctrl+Enter (Cmd+Enter on a Mac) sends too.
Your message appears on the right, and the reply streams in beneath it
as your assistant writes it.

While your assistant is working on a reply - in this window, or in another browser or tab - the
thread shows a three-dot indicator and the message box stays open so you can keep typing. The send
arrow becomes **Add to current turn** - or **Queue message** while a file is attached - and a
separate **Stop** button appears beside it. Select **Stop**
to end the reply early, including one that another device started. If the stop request fails, the
thread shows **Could not stop the reply:** followed by the reason, and the reply keeps running.
See [Keep chatting while a reply is streaming](#keep-chatting-while-a-reply-is-streaming) for what
Enter does in the meantime, and
[Use several browsers or devices at once](#use-several-browsers-or-devices-at-once) for the full
multi-device behaviour.

If you have not opened a chat yet (for example, the first time you use a new browser), you see a
greeting (**Good morning**, **Good afternoon** or **Good evening**), a line that reads **What can
[your assistant's name] help with?**, and three suggestion buttons: **Plan my day**, **Help me
think** and **Summarise what I missed**. Selecting a suggestion copies its words into the message
box so you can edit them - it does not send anything until you press Enter. Your first message
creates a chat for you automatically.

Hover over a reply to reveal its buttons. **Copy** copies the reply to your clipboard, and
**Reply** quotes it (see [Reply to a message](#reply-to-a-message)). Hover over a message of your
own to reveal **Reply** too. **Read aloud** reads the reply out loud; see
[Read a reply aloud](#read-a-reply-aloud). The remaining buttons beside **Copy** are described in
[Controls that are not available yet](#controls-that-are-not-available-yet).

The strip under the message box shows the connection state (**Connected**, **Reconnecting...** or
**Offline**) and a reminder that your assistant can make mistakes.

Text you have typed but not sent yet is kept in this browser for the chat you have open, so it
comes back after a page reload. It is cleared once the message is sent, or when you log out.
Attached files are not kept this way: attach them again after a reload.

### Reply to a message

Hover over a message (yours or your assistant's) and select **Reply** to quote it. A chip above
the message box shows who wrote it (**You**, or your assistant's name) and the first part of the
message, about 140 characters. Select the chip's **x** (**Dismiss reply**) to remove the quote
before sending. Your next message carries the quote, and your message shows the same quote above
it from then on, including when you reopen the chat later.

- **Reply** only appears on messages that have been saved to the chat. A message you have just
  sent, or a reply that has just finished, may not offer it until you reopen the chat: switch to
  another chat and back, or reload the page.
- A quote belongs to one chat. Switching to another chat discards it, and sending a message uses
  it up, even if that send fails.
- You cannot quote a message while a reply is still being written. If you try to add to the
  current turn, or queue, with a quote in place, the message box shows **Replying isn't supported
  yet while a reply is streaming. Wait for it to finish, or remove your reply and send a plain
  message.** Nothing is sent, and your quote and text stay where they are.

### Read a reply aloud

Hover over a reply and select the speaker button (**Read aloud**) to hear that reply spoken. The
button plays the whole reply, however long it is: long replies are spoken in consecutive pieces
with no action needed from you. While it plays, the button becomes **Stop reading**; select it
again to stop. Starting another reply, starting Voice mode, switching to another chat, or losing
the connection stops playback too.

Your assistant reads the text of the reply: paragraphs, headings and list items, spoken in order.
Code blocks, tables and embedded HTML are skipped, so a reply that contains only code or a table
shows **Nothing to read aloud in this reply.**

If the button is dimmed instead, hover over it to see why. **Read aloud — unavailable while
offline** means the connection is down; it comes back on its own once you are connected again.
**Read aloud — unavailable during Voice mode** means a Voice conversation is active (listening,
thinking or speaking); the button comes back when Voice mode is off. **Read aloud — unavailable on
this gateway** means the person who manages WednesdayAI has turned the feature off, or has not
configured a voice for your assistant to speak with. Ask them to enable it; see
[Text-to-speech](/tts) for the setting.

If reading fails, a short message appears beside the button: **Read aloud is turned off for this
assistant.**, **Couldn't play the audio in this browser.**, or **Couldn't read aloud:** followed by
the reason. Nothing is sent to your assistant when you use the button.

### Choose a model and Think

The button at the top of the screen, beside the menu button, shows your assistant's name and the
model this chat is using, for example **Assistant name · Model name**. Select it to open a menu
with **Assistant default** and every model your assistant is set up to use. A tick marks the
current choice. Picking a model applies to this chat only and takes effect on your next message;
other chats are not affected. If the change is refused, the reason appears under the button and
the tick stays where it was. Picking a model with no chat open shows **No chat is open**.

The **Think** button in the message box opens a level menu (**Off**, **Low**, **Medium**, **High**)
plus a **Send reasoning** switch. These apply to this chat only, like the model. A tick marks the
current level. **Send reasoning** controls whether reasoning is delivered with replies; it does
not control what this browser displays.

**Think** is dimmed when the chat's current model does not support extended thinking. Hover over it
to see **Think — [model name] does not support extended thinking**. Switch to another model, or
pick one that does, to use it. A refused change shows its reason under the button.

### Choose what the conversation displays

<Steps>

<Step title="Open Display">
Open **Display** in the top bar.

You should see **Show reasoning** and the **Hide**, **Minimal** and **Full** choices under
**Tools**.
</Step>

<Step title="Choose reasoning visibility">
Turn **Show reasoning** on if you want to see reasoning included with replies.

Replies that contain reasoning show a collapsed **Reasoning** section that you can expand.
</Step>

<Step title="Choose tool details">
Choose how tool activity appears.

The conversation updates immediately: **Minimal** shows compact expandable rows, **Full**
shows calls and results separately, and **Hide** removes normal tool details while leaving
errors and failures visible.
</Step>

</Steps>

The display choices work as follows:

- **Show reasoning** is off by default. Turn it on to reveal collapsed **Reasoning** sections
  when a reply includes reasoning, then expand a section to read it.
- **Tools → Minimal** is the default: each tool invocation appears as a compact expandable row,
  with its result paired when available. Expand it to inspect arguments and the result.
- **Tools → Full** shows calls and results separately, including their structured details.
- **Tools → Hide** removes normal tool call and result details, but keeps tool errors and failures
  visible so you still know when something went wrong.

These choices are remembered in this browser for this WednesdayAI connection. They do not change
the model's Think level or **Send reasoning**. **Show reasoning** only changes whether reasoning
already included with a reply is displayed; it cannot generate reasoning or add it to a saved
reply. Completed replies load their saved tool details without requiring a page reload.

### Keep chatting while a reply is streaming

You do not have to wait for a reply to finish before sending your next message:

- Press **Enter**, or select the send arrow (**Add to current turn**), to add your message to the
  current turn: your assistant reads it before its next step, without waiting for the reply to
  finish. The message appears in the thread straight away. On a phone or tablet, Enter adds a new
  line instead - tap the send arrow. If your assistant cannot take the message right now, it is
  queued instead and marked **Queued**.
- With a file attached, the send arrow reads **Queue message** instead, and queues the message and
  the file for after the reply.
- To queue on purpose, select the small arrow beside the send arrow (**Send options**) and choose
  **Send after reply**, or press **Ctrl+Enter** (**Cmd+Enter** on a Mac) on a computer. A queued
  message appears in the thread marked **Queued** and is sent as soon as the current reply
  finishes. The label goes away when your assistant starts on it. Until then, queuing keeps
  working. A queued message that is still waiting when you reload the page in the same browser tab
  comes back marked **Queued**.
- **Stop** ends the current reply early at any time, including a reply started in another browser
  or tab.

While the reply is in progress, the message box shows **Add to [your assistant's name]'s current
turn...** as its hint text.

Whichever way you send it, your message appears in the thread above the reply it produced: a
message added to the current turn shows the moment you select it, without waiting for the
assistant's answer, and a queued message stays above any reply that arrives after it.

Adding to the current turn needs some text, and cannot carry a file. Attachments go with a queued
message, but the **+** button is dimmed while a reply is being written, so attach files before you
start or wait for the reply to finish.

If your assistant refuses the message, the thread shows **Could not add to the current turn:** or
**Could not queue that message:** followed by the reason (for example `dropped_by_queue_policy`,
when the assistant's queue settings discard the message). The text you typed returns to the
message box so you can send it again; any attachments do not come back. If the reason is unclear,
ask the person who manages WednesdayAI.

### Dictate and voice

Two buttons beside the send arrow turn your voice into a message: a microphone (**Dictate**) and
a wave (**Voice mode**). Whichever one is on stays pressed and highlighted, so the buttons show at
a glance whether they are off or on. Either may be dimmed, independently, depending on what the
person who manages WednesdayAI has configured — see
[Controls that are not available yet](#controls-that-are-not-available-yet) if both are dimmed for
you.

**Dictate** turns your speech into typed text in the message box, without sending anything on its
own:

<Steps>

1. Select the microphone button and allow microphone access when your browser asks.

   The button stays pressed while Dictate is on.

2. Speak. Your words appear inside the message box as you talk, greyed out and replacing
   themselves as they are recognized. While Dictate is on, the message box cannot be edited and
   Send is unavailable; while it is still empty, its hint reads **Listening...**.
3. Select the microphone button again to stop. The button reads **Transcribing...** briefly while
   your last words are recognized, and cannot be pressed then. The words are then placed where
   your cursor was - or at the end of what you had typed - and you can edit them and send as
   usual.

</Steps>

If stopping fails, the words heard so far stay in the message box, so nothing you said is lost.

**Voice mode** has a live, spoken conversation with your assistant instead:

<Steps>

1. Select the wave button and allow microphone access when your browser asks.

   The button stays pressed while Voice mode is on. Above the message box, a pulsing dot shows
   **Listening**, **Thinking** or **Speaking**.

2. Speak normally. Your assistant answers aloud, using the same chat and its recent history as
   typed messages. Live captions show what it heard you say and what it is saying. Once each turn
   is saved, the exchange appears in the thread as text.

3. To interrupt, start talking once the actual reply is speaking. Playback stops almost immediately
   and you can keep talking. The chat keeps only the part of the reply you heard, marked
   **interrupted**.

4. Select the wave button again (**Stop voice mode**) to end the conversation and release the
   microphone.

</Steps>

A short phrase may play while your assistant is still thinking (for example "One moment."), and
another when it starts using a tool on your behalf (for example "Working on that."). Both are
normal. Talking during those short phrases does not interrupt the reply. You can interrupt once
the actual answer starts speaking. A cough, a short "mm-hmm", or your assistant's own voice
reaching the microphone should not cut the reply off either.

Your WednesdayAI may be set up for a faster, more natural voice that talks with you directly. In
that setup, an interrupted reply appears in the chat only as **[interrupted]** (what you said is
still saved), and your assistant can look things up but cannot make changes by voice, for
example editing files. Type those requests instead. In that setup the voice service detects your
speech itself, so talking over the short acknowledgement can cut it off too.

If the strip under the message box changes to **Reconnecting...** or **Offline**, the microphone
is released. Voice mode returns to the unpressed wave button, even if it was still starting.
Dictate stops too, and the microphone button's tooltip reads **Voice input stopped because the
connection dropped.** The words heard before the drop stay in the message box, ready to edit and
send. Wait until the strip says **Connected**, then select the button again.

If either button shows an error (for example after you deny microphone access, or if this browser
cannot use a microphone), the button gets a red outline and its tooltip shows the reason. Select
it again to retry. Both release the microphone fully when you stop them, when the connection
drops, or when you leave the page.

### Attach files

Select the **+** button (**Attach files**) in the message box, or drag files onto it. You can
attach several at once. The web client accepts any file type, up to 32 files, 5 MB each and
18 MB total per message (images show a thumbnail; other files appear as a card). Images are
described automatically when the chat's model cannot see images. Each attachment appears as a small
card above the message box; select its **x** to remove it before sending. A file that is empty,
larger than 5 MB, or that pushes the message over 18 MB or 32 files is rejected before anything is
sent, with a message under the message box explaining why. The **+** button is dimmed while a file
is uploading or a reply is being written.

### See older messages

Scroll to the top of a conversation and select **Load older messages** to fetch earlier history.
The button reads **Loading...** while it works. Your place in the conversation stays put while
older messages load. The button disappears once there is nothing older to load. If loading fails,
the thread shows **Could not load older messages:** followed by the reason; select the button to
try again.

The conversation follows the newest message on its own, but only while you are near the bottom. If
you scroll up to read something earlier, new text does not pull you back down.

## Switch between chats

Each separate conversation is a **chat**. Your chats are listed in the sidebar under **Chats**,
with the most recently updated first. Each row shows the chat's title and its **session key**,
the full identifier of that conversation, such as `agent:main:telegram:direct:example-user`.
Long keys are shortened visually; hover over a row to read its full key. A colour dot identifies
the assistant, and a small tag identifies chats from another app, such as Telegram or Discord. A
chat whose assistant is working on a reply, or that has unseen replies, also shows a small dot
beside its title - see
[Use several browsers or devices at once](#use-several-browsers-or-devices-at-once).

With no chats yet, the list reads **No chats yet**.

Scheduled jobs, isolated heartbeat checks, subagents and other internal conversations are hidden
by default. Turn on **Show internal** beside **Chats** to include them. A normal conversation that
also contains heartbeat activity is not hidden.

Use the **Sort chats** control to choose **Newest**, **Oldest**, **Title A-Z**, **Title Z-A**,
**Key A-Z** or **Key Z-A**. Sorting, assistant filtering, search and **Show internal** apply to your
entire conversation history before a page of results is shown, not only to chats already loaded in
the sidebar. Time-based sorts group chats into **Today**, **Yesterday** and **Earlier**;
alphabetical sorts show one ungrouped list.

- Select a chat to switch to it. If the chat cannot be loaded, the thread shows **Could not load
  this chat:** followed by the reason.
- Select **New chat** at the top of the sidebar to start a fresh conversation in one step. It uses
  the assistant you are filtering the list by (see below) if there is one, otherwise the assistant
  of the chat you have open. The new chat is named **New chat**, then **New chat 2** and so on. If
  it cannot be created, the thread shows **Could not start a new chat:** followed by the reason.
- Select the small arrow beside **New chat** (**New chat with...**), or **Browse assistants**
  further down the sidebar, to open the **New chat with...** window: a list of every assistant you
  can talk to, each with its own colour, and a **Model** menu that starts on **Assistant default**.
  Pick a model if you want one, then select an assistant to start a fresh chat with it right away
  (the row shows **Creating…** while it works). If models cannot be loaded the window says
  **Could not load models — the assistant default will be used.** and you can still pick an
  assistant. A failed create shows the reason in the window so you can try again. Close it with
  **Close**, **Escape**, or by clicking outside it.
- Type in the **Search chats** box at the top of the sidebar to filter the list. The list updates
  shortly after you stop typing; select the **x** in the box (**Clear search**) to see every chat
  again.
- Once you have more chats than fit on one page, a **Load more** button appears at the bottom of
  the list.

Switching chats while a reply is still being written is fine: the new chat's message box works
straight away.

While **Dictate** or **Voice mode** is on, switching chats is blocked: selecting another chat, the
unread bell, an assistant, or **New chat** only shows a notice - **Stop dictation to switch
chats.** or **Turn off voice to switch chats.** Stop the one that is on, then switch.

On a wide screen, the button in the sidebar header collapses the sidebar to a thin strip; select
the strip's button to bring it back. On a phone or a narrow window the sidebar is hidden. Open it
with the menu button at the left of the top bar, and close it with the **x** at the top of the
sidebar or by tapping outside it. On a phone the page itself never scrolls: the conversation
scrolls inside its own area, and the top bar and message box stay where they are - including with
the on-screen keyboard open - and typing into a box never zooms the page.

The **Assistants** section lists assistants with an eligible chat updated within the last
**4 hours**, by default. Choose **1h**, **2h**, **4h**, **8h**, **16h**, **24h** or **All** with the
activity-window control. **All** includes assistants with no chats. The assistant you have selected
stays pinned and visible even when its chats are older than the window. The assistant for the chat
you currently have open also stays visible when you have not selected a filter.

Use **Sort assistants** to choose **Newest**, **Oldest**, **Name A-Z** or **Name Z-A**. Newest and
oldest use each assistant's most recently updated eligible chat, not its oldest chat. Internal
conversations contribute only when **Show internal** is on. The activity window narrows the
assistant list, not the age of chats shown after you select an assistant.

Select an assistant to highlight it, show its chats and reopen the last chat you selected with
that assistant. If that chat was deleted or is excluded by **Show internal**, the newest
user-facing chat opens instead. An assistant with no eligible chat opens an empty conversation
view without creating a chat. Sending the first message creates a chat for that assistant;
you can also select **New chat** to create one explicitly.

Selecting the same assistant again keeps it selected; it does not clear the selection. Select
**All assistants** when you want to clear the assistant filter and show chats from everyone. Your
currently open chat stays open. Sorts, filters, the selected assistant and remembered chats persist
across reloads in this browser. Each assistant's colour also marks its chats and appears beside its
name in the top bar.

### Rename a chat

Select the chat's title at the top of the screen (it reads `/` followed by the title) to edit it in
a box labelled **Chat title**. A title can be up to 60 characters.

- Press **Enter** to save. Clicking elsewhere also saves. Press **Escape** to cancel.
- An empty or unchanged title closes the box without saving anything.
- If the change is refused, the reason appears beside the box and the box stays open. For example,
  `label already in use: [title]` means another chat already has that title.

The sparkle button beside the box (**Suggest a title**) writes a title for you from the first
message shown in the thread and puts it in the box. It does not save: press **Enter** to keep it,
edit it first, or press **Escape** to discard it. Until the chat has a message, the button does
nothing and its tooltip reads **No message to summarise yet**.

Suggesting titles is limited to 3 per minute. Past that, the box shows **rate limit exceeded for
sessions.title.prepare; retry after 60s** (the number of seconds varies). Wait that long and select
the button again, or type a title yourself. If no title could be produced, the box shows **Could
not suggest a title**.

### This chat changed elsewhere

Each send is checked against the latest message this window has shown you. If the chat has moved on
since then - because you or your assistant added to it from another browser, another device or
another app - your message is still sent: the thread refreshes to show the messages you had not
seen, and the message is sent again automatically against the refreshed chat. Attachments and a
reply quote go with the resent message. You normally notice nothing except the new messages
appearing above yours.

A banner reads **This chat changed elsewhere. The latest messages are shown below.** only when the
chat changes a second time while that automatic retry is under way. The text you typed is put back
in the message box (an attached file or a quote is not), so read what is new and press Enter again
if you still want to send it. If you switch to another chat while the automatic resend is being
prepared, the resend is cancelled and your text is put back in the message box instead. Select
**Dismiss** to hide the banner; it also clears on your next send or when you switch chats. Queued
messages, and messages added to the current turn, are not checked this way.

## Use several browsers or devices at once

You can have the web client open in several browsers, tabs and devices at the same time. A reply
appears in every one of them without reloading the page: the window that sent the message shows
the reply as it is written, and the others show the working indicator until it is ready, then the
full exchange.

While your assistant is working on a reply anywhere, the chat shows it in three ways:

- The thread shows the three-dot indicator described in
  [Send a message](#send-a-message), including in a chat that does not have any messages yet.
- The chat gets a small pulsing dot in the sidebar.
- The message box offers **Stop**, **Add to current turn** and **Send after reply** as usual, and
  they work on that reply even though another device started it.

The Runs panel lists the same work in progress; see [Check on Runs](#check-on-runs). Sending into
a chat that gained messages elsewhere meanwhile is covered in
[This chat changed elsewhere](#this-chat-changed-elsewhere).

A chat counts as **unread** in this browser (or installed app) when an assistant reply arrived
since you last had that chat open here. Replies a chat already had the first time this browser
sees it do not count: the unread baseline starts at what is on screen. Unread chats show a small
dot in the sidebar - on the chat's row and on the chat's assistant - and an assistant with unread
replies stays listed even when its newest chat is older than the activity window. The bell in the
top bar shows a count of unread chats. Select the bell to see the list: choose a chat to open it,
or choose **Mark all as read** to clear every unread mark at once. That choice is offered only
while something is unread; with nothing unread the panel reads **You're all caught up**. The
tab's title shows the number of unread chats, for example **(2) WednesdayAI**. Unread marks are
kept in this browser (or installed app) and are not shared with your other devices, so they
survive closing the page, the device sleeping and a dropped connection. Opening the chat clears
its mark, and so does returning to the tab while it is open. If a chat is deleted elsewhere while
you are away, its unread mark is dropped the next time the chat list is read in full on one page
and that chat is not in it. These work whether or not you turn on the notifications described
below.

To also get a desktop notification when a reply arrives while the tab is hidden, open the account
menu (select your name at the bottom of the sidebar), find **Notifications** and choose **On**.
Your browser asks for permission; choose **Allow**. While it is on and the tab is hidden, a
notification names the assistant that replied and the chat it arrived in - never the reply text -
and selecting the notification opens that chat. The choice is remembered in this browser for this
WednesdayAI connection, like the theme.

If your browser has blocked notifications for this site, the menu shows
**Blocked in browser settings** and the choice stays **Off** until you re-allow notifications for
this site in the browser's settings. On browsers without desktop notification support - most
mobile browsers - the menu shows **Not supported in this browser**; there, the bell, the sidebar
dots and the title count are the notification.

Coming back to a tab you left in the background also catches the open chat up: messages that
arrived elsewhere are fetched and shown without a reload.

## Check on Runs

**Runs** are things your assistant is doing or has done - answering you, working through a task,
and so on. The **Runs** row under **Extensions** in the sidebar shows a number badge whenever
something is running, even while the panel is closed.

Select **Runs** to open a panel with four groups:

| Group               | Meaning                                               |
| ------------------- | ----------------------------------------------------- |
| **Queued**          | Waiting to start.                                     |
| **Running**         | In progress right now.                                |
| **Needs attention** | Stopped in a state that needs a person to look at it. |
| **Finished**        | Completed, failed, or cancelled.                      |

Select any entry to see more detail about it, and select it again to hide the detail. The panel
updates live as things change. Use **Refresh** to check now, **Load more** where it appears to see
older entries, and **Close** (or select **Runs** again) to close the panel. On a phone the panel
opens as a full-screen sheet over the conversation, and **Close** returns you to the chat.

The Runs panel only shows live data when the person who manages WednesdayAI has set up SQLite or
Postgres storage for it. Without that, every group reads "Nothing here.", a message under the
groups explains the storage requirement, and the badge stays hidden. Ask them if you need it.

If the assistant's server restarts while the panel is open, the lists stay as they are - rows do
not disappear - and a message under the groups says **Gateway is starting; runs will refresh
shortly** until the lists fill in again on their own. If the storage behind the lists fails to
start, the lists empty and the message instead reads **Session storage failed to start; see
gateway status**, staying until that is fixed. A message you sent that was still waiting to start
before the restart is kept, not dropped: it shows up again once the server is back (see
[Keep chatting while a reply is streaming](#keep-chatting-while-a-reply-is-streaming)). The
browser tab keeps such a message for up to 24 hours; after a longer outage it is discarded.

## Choose a theme

Select your name at the bottom of the sidebar to open the account menu, then pick a **Theme**:

| Theme             | What you get                                                                                          |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| **Auto**          | Follows your device: dark or light, or high contrast if you have asked your device for more contrast. |
| **Dark**          | Always dark.                                                                                          |
| **Light**         | Always light.                                                                                         |
| **High contrast** | Brighter text and stronger outlines, for low vision or bright rooms.                                  |

The change applies immediately and is remembered on this browser. If you previously chose the older
**Black** or **White** theme, WednesdayAI carries that over to **Dark** or **Light**. The theme also
sets the colour of your browser's own scroll bars and form controls, so they match the rest of the
page. Animations are skipped if your device is set to reduce motion.

## Controls that are not available yet

Some controls are visible but switched off because the feature behind them is not ready. They look
dimmed. Hover over one (or focus it with the keyboard) to see a tooltip such as "Canvas — coming in
phase P4". Selecting one does nothing and sends nothing to your assistant. (**Think** can also be
dimmed, but for a different reason: see [Choose a model and Think](#choose-a-model-and-think).)

| Where            | Controls                                    |
| ---------------- | ------------------------------------------- |
| Top bar          | **Canvas**                                  |
| Sidebar          | **Calendar**, **Memory**, **Add extension** |
| Account menu     | **Settings**, **Keyboard shortcuts**        |
| Message box      | **Search**                                  |
| Under each reply | **Feedback**, **Regenerate**                |

The tooltip for **Canvas** names a numbered phase. The tooltips for **Calendar**,
**Memory**, **Add extension**, **Settings**, **Keyboard shortcuts**, **Search** in the message
box, **Feedback** and **Regenerate** read "coming with the extension panel SDK" followed by a
tracked issue number. The **⌘N** label beside **New chat** is only a hint for now: no keyboard
shortcut is wired up to it.

**Dictate** and **Voice mode**, the microphone and wave buttons beside the send arrow, are not on
this list — see [Dictate and voice](#dictate-and-voice). Either can still be dimmed when the
person who manages WednesdayAI has not turned on and configured that control's voice service yet;
the tooltip then reads **unavailable on this gateway**. Ask them to enable it if you want to use
it.

**Read aloud** is not on this list either: the button works, or is dimmed with the reason beside
it - see [Read a reply aloud](#read-a-reply-aloud).

## Sign out

Select your name at the bottom of the sidebar to open the account menu, then select **Log out**.
This clears this browser's access - you (or whoever uses this browser next) will need a new setup
code to sign back in here. It does not affect any other browser or device paired with your
assistant.

## Troubleshooting

### The bottom of the screen says "Offline" or "Reconnecting..."

The web client lost its connection and reconnects on its own - this is normal after a network
hitch, when your computer wakes from sleep, or when the assistant's server restarts. Returning to
the tab or coming back online retries immediately. Nothing is lost while this happens: a reply that
finished while you were away appears once, and a reply cut short by a restart shows a notice (see
the next item). If it still has not recovered after a minute, reload the page.

### A notice says the reply was interrupted

If the assistant's server restarted while a reply was being written, the thread shows **The gateway
restarted before this reply finished. Your message was delivered; send it again to retry.** Your
message arrived - nothing was lost. The old reply does not continue on its own, so send the message
again if you still want an answer.

### The Runs panel says the gateway is starting

Right after a restart the panel keeps what it showed and says **Gateway is starting; runs will
refresh shortly**. It fills in again on its own - no action needed. If it instead says
**Session storage failed to start; see gateway status** and the message stays, the storage behind
the lists did not start; tell the person who manages WednesdayAI, who can see the cause in the
gateway status.

### Dictate or Voice mode will not start, or the button is dimmed

A dimmed microphone or wave button means the person who manages WednesdayAI has not turned that
control on yet. Ask them to enable it. If the button is available and then shows an error, allow
microphone access in the browser's site settings, reload the page, and select it again. If the
tooltip says this browser cannot capture microphone audio, use a current desktop browser over
HTTPS (or `localhost`).

### Read aloud will not start, or the button is dimmed

Hover over the dimmed speaker button to see the reason: wait for the connection to come back
(**unavailable while offline**), turn off Voice mode (**unavailable during Voice mode**), or ask
the person who manages WednesdayAI to turn the feature on (**unavailable on this gateway**). If
the button is available but a message appears beside it instead of audio, the message says what
went wrong - for example **Read aloud is turned off for this assistant.**, or
**Couldn't play the audio in this browser.**, which usually means the browser is old or missing
audio support: try a current desktop browser. See
[Read a reply aloud](#read-a-reply-aloud).

### Talking does not interrupt the reply

Interruption works only while the actual reply is speaking, not during the short "One moment" or
"Working on that" phrases, and not for a cough or a brief "mm-hmm". Wait until the reply itself
is playing, then speak a real sentence. If your first words after a reply are missed, pause
briefly or use a headset so speaker echo is not mistaken for you.

### Voice mode or Dictate stops by itself

Check the strip under the message box. **Reconnecting...** or **Offline** releases the microphone
and returns Voice mode to the wave button. That is expected. Select the button again after the
strip says **Connected**. If the strip stays **Connected** and the conversation still ends, try
once more and tell the person who manages WednesdayAI the time it failed.

### On iPhone or iPad, Voice mode starts but you hear no reply

On iPhone and iPad, Safari only lets a page start playing audio from inside a tap. Voice mode
connects to the voice service after you select the button, so on iOS the spoken reply can be
silenced even while the status shows **Speaking**. If that happens, stop Voice mode and use
**Dictate** or typed messages instead; typed chat is unaffected. This is a known gap on iOS.

### I cannot switch chats while Dictate or Voice mode is on

That is expected: while one of them is on, selecting another chat, the unread bell, an assistant,
or **New chat** only shows a notice - **Stop dictation to switch chats.** or **Turn off voice to
switch chats.** Select the pressed microphone or wave button once to stop it, then switch. See
[Switch between chats](#switch-between-chats).

### You are suddenly asked to pair again

Short interruptions - the assistant's server restarting, a flaky connection - no longer sign this
browser out; it reconnects on its own and you keep your chats. If you are genuinely asked to pair
again, this browser's access was removed or has expired. Ask the person who manages WednesdayAI for
a new setup code.

### A file will not attach

Check that the file is under 5 MB, is not empty, and that the attachments for the message stay
within the limits: 32 files in total and no more than 18 MB across all of them. Any file type is
accepted.

### The message box will not send, or shows an error

While a reply is being written, Enter adds your message to the current turn, or queues it, instead
of sending it straight away; see
[Keep chatting while a reply is streaming](#keep-chatting-while-a-reply-is-streaming). If the
thread shows **Could not add to the current turn:** or **Could not queue that message:**, your
text is back in the message box. The same happens when an ordinary send finally fails - for example after repeated
connection trouble: the thread shows the reason as a system message and your text returns to the
message box, ready to send again. If the box says **Replying isn't supported yet while a reply is
streaming...**, remove the quote with its **x** or wait for the reply to finish. If the bottom of
the screen says **Offline** or **Reconnecting...**, see the first item in this list.

### A notice says the chat changed elsewhere

Your message was still sent: the thread refreshed to show what this window had not seen, and the
message went out again automatically (see
[This chat changed elsewhere](#this-chat-changed-elsewhere)). The banner appears only when the
chat changes a second time during that retry. Your text is back in the message box; an attached
file or a quote is not, so add them again before sending.

### Suggest a title says "rate limit exceeded"

Suggesting titles is limited to 3 per minute. Wait for the number of seconds shown and try again,
or type a title yourself.

### I am not getting desktop notifications

Check four things, in order: **Notifications** is **On** in the account menu; the browser has
granted notification permission for this site - if the menu reads **Blocked in browser settings**,
re-allow notifications for this site in the browser's site settings; the tab is actually in the
background, because notifications are only shown while it is hidden; and the browser supports
them at all - most mobile browsers do not, and the menu reads
**Not supported in this browser**. The bell, the sidebar dots and the title count work in every
browser.

### A chat stays unread after I open it

Opening a chat clears its unread mark in the browser that opened it. If the dot is still there,
you probably opened the chat in a different browser or the installed app than the one showing the
dot: unread marks are kept per browser or installed app and are not shared between them. Reload
the page that shows the dot, and open the chat once there.

### A reply arrived but nothing shows as unread

The bell, the dots and the title count need to know when each reply was written. If the gateway
is older than the web client, replies can only be counted while the page is open, so a reply that
arrived while the page was closed or the connection was down is not marked. Ask the person who
manages WednesdayAI to update the gateway. If your browser clears site data between visits (for
example some private-browsing modes), unread marks kept for this site go with it too.

### A control does nothing when I select it

It is probably one of the [controls that are not available yet](#controls-that-are-not-available-yet).
Hover over it to see when it is planned. If it is **Think**, see
[Choose a model and Think](#choose-a-model-and-think).

### Reasoning does not appear after I turn on Show reasoning

**Show reasoning** can display only reasoning available in the reply; it cannot add reasoning to
an existing reply. **Send reasoning** controls delivery for new replies, separately from this
browser's display choice. Check that setting in **Think** before sending a new message. Some
models or replies may not produce reasoning even when that switch is on.

### Display, sorting, or assistant choices reset after a reload

The web client saves these choices in this browser. If it cannot read saved choices, it starts
with the defaults: reasoning hidden, tools shown in **Minimal** form, assistants from the last
**4 hours**, assistants sorted by **Newest**, chats sorted by **Newest**, internal chats hidden,
and no assistant filter. If it cannot save a change, your choice still works while the page is
open, but a reload may restore an older saved choice or a default. You can still navigate and
chat. Check your browser's privacy or storage settings if you want your choices remembered.

### The page shows a connection error and never loads chat

The address that hosts the web client may not be allowed to talk to your assistant yet, or the
address itself may be wrong. Contact the person who manages WednesdayAI and share the exact web
address you tried.
