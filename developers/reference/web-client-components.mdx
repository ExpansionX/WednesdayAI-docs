# Web client components

`apps/web` is the end-user web client (client id `openclaw-user-client`). Its view layer is a small
native React component layer under `apps/web/src/ui/`, styled over the shared
[Brand tokens](/reference/brand-tokens). This page is the contract for changing it. For hosting and
configuration see [Web client hosting](/web/user-client).

## Layout

```text
apps/web/src/
  app/         App (boot phases), AppShell (connected shell) and the use-chat-* hooks it composes, onboarding and config-error views
  ui/          the component layer: Shell, Sidebar, TopBar, Thread, Composer, ... + client.css
  state/       chat.ts (zustand store), types.ts
  providers/   gateway and events seams, WebClientRuntime, theme, attachments, preferences, and the chat runtime modules (leaf tracking, queued turns, chat list)
  runs/        RunsController and the projection behind the Runs panel
  gateway/     connection, device identity, setup-code parsing
```

The components in `ui/` are `Shell`, `Sidebar`, `NavigationMenus`, `TopBar`, `ModelMenu`, `ThinkMenu`,
`DisplayMenu`, `ToolDisplay`, `AssistantPicker`, `AccountMenu`, `AttentionMenu` (the top-bar unread
bell), `Thread`, `TypingIndicator`,
`AssistantMessage`, `UserMessage`, `EmptyState`, `Composer`, `RightPanel`, `DisabledControl`,
`Icon` and `markdown/MarkdownRenderer`. `Shell` owns layout mechanics (mobile
breakpoint at 860px, sidebar open and collapsed state) so `AppShell` supplies data, not chrome. The
assistant and chat controls client-chat-v3 P2 made live (model, Think, assistant picker, queue,
reply, rename) are covered under [Chat controls and hooks](#chat-controls-and-hooks).

## Styling conventions

- Every class in `apps/web/src/ui/client.css` is prefixed `cl-` (`cl-sidebar`, `cl-composer`,
  `cl-msg`). There is no shadow DOM and no CSS-in-JS. Boot views (loading, pairing, configuration
  error) live in `app/app.css` with a `boot-` prefix.
- Colours, spacing, radii, motion and fonts come from `brand-tokens` custom properties. Never
  hard-code a colour or font family. Text on an accent fill uses `--accent-foreground`.
- A token only this app needs (`--personalise-subtle`, `--composer`, `--shadow-md`) is declared at
  the top of `client.css`, not in the shared package.
- Icons are inline SVG paths in `ui/Icon.tsx` (Lucide-style, ISC notice in `apps/web/NOTICE`). Add a
  glyph to `IconName` rather than an icon-library dependency.
- Markdown replies render under a `.prose` wrapper. Style prose elements under `.prose`, not by
  element selector on the page.
- Honour `prefers-reduced-motion`: entrance animation is disabled under it.
- Tests and e2e suites select by `data-testid` and `data-role`, never by `cl-` class. Keep an
  existing hook stable when you restyle; rename it in the same change as the suites that use it.

## DisabledControl and the phase contract

A control whose backing feature ships later renders through `DisabledControl`
(`apps/web/src/ui/DisabledControl.tsx`), visible but inert:

```ts
type DisabledPhase = "P4";

type DisabledControlProps = {
  label: string;
  icon?: IconName;
  className?: string;
  testId?: string;
  dataAttrs?: Record<string, string>;
  children?: ReactNode;
} & (
  | { phase: DisabledPhase; finding?: never; reason?: never }
  // tooltip: "<label> — coming in phase <phase>"
  | { phase?: never; finding: string; reason?: never }
  // tooltip: "<label> — coming with the extension panel SDK (<finding>)"
  | { phase?: never; finding?: never; reason: string } // tooltip: "<label> — <reason>"
);
```

The contract:

- It renders a `<button type="button" aria-disabled="true">` with a `title` tooltip. It uses
  `aria-disabled`, not the `disabled` attribute, so it stays focusable and the tooltip is reachable
  from the keyboard.
- The click handler only calls `preventDefault()`. A disabled control must never reach a gateway
  RPC, whatever capability flag is set. `features.voice` is deprecated and ignored: it never
  enabled Dictate or Voice mode, and now has no reader at all — both controls' live/disabled state
  is `talk.catalog`-driven (ADR 0088 item 12, amended): Dictate needs a configured streaming
  transcription provider and the gate on, Voice additionally needs a configured streaming speech
  provider.
- The props are a union: pass **exactly one** of `phase`, `finding` or `reason`. Use `finding` for controls that wait on a tracked finding rather
  than a phase: Calendar, Memory and Add extension cite `"F1, GitHub #634"`, and the P2 retags (message
  feedback, message regenerate, account-menu settings, account-menu keyboard shortcuts, composer
  search) each cite their own finding (`"F-2026-09-29-1x, GitHub #69x"`, ADR 0085 M9); the
  `finding` tooltip wording is fixed, so it reads "coming with the extension panel SDK" whichever
  finding it cites. Use `reason` for capability-driven unavailability that is not roadmap work:
  the `reason` text is rendered verbatim after the label, so it names why this connection cannot
  use the control — Dictate and Voice mode pass `"unavailable on this gateway"` when `talk.catalog`
  does not offer them, Read aloud passes the same reason strings when the gateway gate is off or
  the client is offline ([Read aloud](#read-aloud)), and the account
  menu's notifications toggle passes `"Not supported in this browser"` where there is no
  `Notification` constructor.
- Give it a `testId`. The brand e2e asserts that each disabled control has `aria-disabled="true"`,
  a tooltip naming its phase, finding or reason, and sends no gateway frame when activated.

```tsx
// Do this: the TopBar Canvas toggle is live while the Assistant UI plugin may be available
// (canvasEnabled !== false), and a DisabledControl carrying the availability reason when the
// feature is off.
{
  canvasEnabled === false ? (
    <DisabledControl
      label="Canvas"
      icon="canvas"
      className="cl-tb-btn"
      testId="top-bar-canvas"
      reason="Assistant UI is off"
    />
  ) : (
    <button
      type="button"
      className="cl-tb-btn cl-tb-canvas"
      data-testid="top-bar-canvas"
      aria-pressed={canvasOpen}
      title="Canvas"
      onClick={onToggleCanvas}
    >
      <Icon name="canvas" />
      <span className="cl-tb-btn__label">Canvas</span>
    </button>
  );
}

// Not this: a live-looking button that calls a method this client is refused
<button onClick={() => gateway.request("talk.metrics", {})}>Metrics</button>;
```

To enable a control when its phase ships, replace the `DisabledControl` with a real element, update
the allowlist ADR if it needs a new method, and update the disabled-control e2e in the same change.

## Assistant UI surfaces and the renderer registry

The assistant can compose inline UI (`show_ui`, the `ui-surfaces` plugin, ADR 0106) using the 14
declarative components from the shared contract catalog. The renderer that maps those component
names to React lives under `apps/web/src/ui/surface/` (registry in `SurfaceView.tsx`,
components in `components/`).

**Import rule.** `apps/web` imports only `ui-contract/types` — never the zod-bearing modules and
never another validator library. The contract package owns the shape and the budgets; the browser
only consumes the parsed snapshot.

**How to add a component.**

1. Add the component to the catalog in `packages/ui-contract/src/types.ts` (`COMPONENT_NAMES` and
   the node interface) and its prop checks to `packages/ui-contract/src/catalog.ts` and
   `surface.ts`.
2. Map it to a React component in `apps/web/src/ui/surface/components/` and register it in the
   registry in `apps/web/src/ui/surface/SurfaceView.tsx` under the same `component` name.
3. Add tests: the contract package test proves the catalog + validation, per-component tests
   `apps/web/src/ui/surface/components/*.test.tsx` prove keyboard operability and axe
   accessibility (SC11), and the web e2e proves the render (`test/user-client-web-surfaces.e2e.test.ts`
   via `test/helpers/user-client-web-harness.ts`).

**Transcript carriers.** Surfaces and actions ride two transcript carriers, never free-form
markdown: `__openclaw.ui` = `{surfaceId, revision}` is projected from the `show_ui` tool result's
`details.ui` at `chat.history` read time, and the snapshot itself is fetched via
`chat.surfaces.get`. `__openclaw.uiAction` = `{surfaceId, revision, actionId, label, title}` rides
the user turn (stored as the `openclaw:ui-action` custom entry) and renders as the
"You submitted" chip; the submitted data is not in it — it reaches the model only in the composed
`[ui-action]` text. Both must survive a reload, which is why they persist as history rows rather
than in a scratch store.

## State and provider seams

Data flows in one direction.

```text
GatewayConnection --frames--> WebClientRuntime --events bus--> AppShell --> zustand store --> ui/*
                    ^                |
                    +--- requests ---+  (gateway seam: sendMessage, switchSession, ...)
```

- `providers/web-client-runtime.ts` (`WebClientRuntime`) owns the connection and implements both
  seams: the `GatewayContextValue` (`providers/gateway.tsx`, request-style calls such as
  `sendMessage`, `switchSession`, `listSessions`, `uploadFile`, `abortMessage`) and the
  `EventsContextValue` (`providers/events.tsx`, subscriptions such as `onChatChunk`,
  `onSessionChanged`, `onSessionsList`, `onConnectionStatus`). It also has WednesdayAI-native
  members the vendored seams have no room for, which the `app/` hooks call directly: `listAgents`,
  `listModels`, `patchSession`, `prepareSessionTitle`, `resolveDirectSession`, `sendChatMessage`
  (the one `chat.send` seam), `steerMessage`, `queueMessage`, `listActiveRunIds`, the `sessionList`
  runtime, and the `onSidebarSessionsChange`, `onActiveSessionRowChange`, `onQueuedRunStarted`,
  `onAssistantReply` and `onActiveLeafConflict` subscriptions.
- `app/AppShell.tsx` subscribes to the events seam once per runtime, writes into the store
  (`state/chat.ts`, `useChatStore`) and composes the hooks described under
  [Chat controls and hooks](#chat-controls-and-hooks). Components read the store or receive props;
  they do not subscribe to the connection themselves.
- The seam interfaces are kept in the shape of their upstream Saturday origin, including members
  the web client no-ops (desktop context, accessibility). Provenance is in `apps/web/NOTICE`.
  The Saturday-era seams with no web client consumer are gone, not no-oped: the events seam's
  `onContextUpdate`, `onSSEStatus`, `onCanvasUpdate` and `onCanvasSync`, their payload types in
  `state/types.ts` (`ContextUpdatePayload`, `SSEStatus`, the Canvas shapes), and the store fields
  and actions they fed (`sseStatus`/`setSSEStatus`, `contextEnabled`/`setContextEnabled`,
  `currentContext`/`setCurrentContext`) are deleted. The wire and preference shapes
  (`StatusResponse.context_enabled`, `Preferences.context_enabled`) stay — they describe gateway
  data, not UI state.
- Runs live in `runs/` behind `RunsController`. Its `start()` and `stop()` are one boolean, so
  components take a **reference-counted lease** with `useRunsLease(controller)`
  (`ui/use-runs-lease.ts`); the Sidebar holds one for the live badge and the `RightPanel` holds
  another while open.

```ts
// Do this: the sidebar badge and the panel each hold a lease
useRunsLease(runsController); // Sidebar: badge stays live with the panel closed
useRunsLease(controller, true); // RightPanel: refresh on join

// Not this: closing the panel would stop the controller and freeze the badge
useEffect(() => {
  controller.start();
  return () => controller.stop();
}, []);
```

- `Thread` does not scroll itself. The scrolling element is the `.cl-scroll` wrapper `AppShell`
  places around it, so scroll code must drive that element. Auto-follow applies only while the
  reader is within 80px of the bottom.

## Reconnect and send integrity

A socket drop or gateway restart during a turn must not show a reply twice, lose a sent message, or
return the user to onboarding. The contracts live in `gateway/connection.ts` (transport) and
`providers/web-client-runtime.ts` (recovery), and the store guarantees live in
`state/chat.ts` and `gateway/message-text.ts`:

- **Socket identity.** Every listener in `openSocket` is bound to its own socket, and
  `handleClose(ws)` returns immediately when the closing socket is no longer the current one.
  A late `close` from an old socket therefore cannot reject the new socket's pending requests, and
  `forceReconnect` (which closes the socket itself and runs the close path) schedules exactly one
  reconnect even though the browser also fires its own `close` event.
- **Liveness watchdog.** `hello-ok`'s `policy.tickIntervalMs` (default 30 000) arms a chained
  `setTimer` check: no frame for two tick intervals closes the socket with code `4000`
  (`tick timeout`) and reconnects, mirroring `src/gateway/client.ts`. `online`, `pageshow` and
  `visibilitychange` (to visible) retry immediately while `reconnecting`, and force a reconnect
  when the resumed page's socket is stale. There is no per-RPC response timeout; the watchdog
  bounds every hang on a dead socket.
- **Transient connect classification.** `isTransientConnectFailure` treats anything that is not a
  `GatewayRequestError`, an `error.retryable` flag, `UNAVAILABLE`, `RECOVERY_NOT_READY`, or a detail
  code in `TRANSIENT_CONNECT_DETAIL_CODES` (`AUTH_RATE_LIMITED`, `DEVICE_AUTH_SIGNATURE_EXPIRED`,
  `DEVICE_AUTH_NONCE_REQUIRED`, `DEVICE_AUTH_NONCE_MISMATCH`) as transient. After onboarding, a
  transient failure keeps the device credential and only reschedules the reconnect, honouring
  `retryAfterMs` (`AUTH_RATE_LIMITED` backs off to `MAX_BACKOFF_MS`). Any other `connect`
  refusal — a credential the gateway no longer accepts (`AUTH_DEVICE_TOKEN_MISMATCH`) is the
  common example — clears the credential and re-runs onboarding.
- **Idempotent sends.** `sendChatMessage` generates one `idempotencyKey` per logical send and
  `requestChatSendWithRetry` re-sends the identical params until the ack arrives, the turn stops
  being this client's pending one (session switch, stop, abandon), `connection.isStopped()`, or
  `SEND_RETRY_DEADLINE_MS` (60 s) has elapsed. A send is retryable when the socket died with the
  request in flight (not a `GatewayRequestError`), `error.retryable` is set, or the code is
  `RECOVERY_NOT_READY`; the delay between attempts is `Math.max(250, retryAfterMs)`. The gateway's
  dedupe answers a repeat whose first attempt landed with `in_flight` or the cached result instead
  of a second run, and a cached result for a turn whose final was missed settles the run locally
  through `settleRunMissedDuringGap`.
- **Reconnect reconcile.** `afterConnect` re-subscribes, then `reconcileOwnRunsAfterReconnect`
  lists the open chat's runs (`sessions.runs.list`) and settles every locally-owned run: `running`
  or `queued` keeps tracking and streaming, `terminal` or absent settles against the transcript
  (the `completed-turn` merge with `completedRunId` and a `done` chunk), and `action-needed`
  (interrupted by a restart) settles as aborted and emits the restart notice as a `chatError`.
  A failed status read changes nothing: tracking and streaming continue and Stop remains the user's
  escape hatch. Queued follow-ups and an unacked pending turn are left to the existing
  `loadHistory` and send-retry paths.
- **Store and stream dedupe.** `prependMessages` drops incoming rows whose `entryId` or `id`
  already exists; `addSyncedMessage` returns state unchanged for an assistant payload whose id
  matches an existing row's `localRunId`; `streamUpdate` opens no second bubble when the final text
  differs from the streamed text only in leading or trailing whitespace.
- **Draft safety.** A definitive send failure (retries exhausted or a non-retryable error) removes
  the optimistic user row (`removeMessage`), restores the text to the composer via
  `handleFillComposer`, and adds the reason as a system message. The composer persists its text per
  session key under `openclaw-user-client:draft:<sessionKey>` in `sessionStorage` (300 ms debounce,
  removed when emptied), reads it back on mount, and merges a restore behind text typed meanwhile
  instead of clobbering it. Logout clears every draft key (`clearAllComposerDrafts`). Attachments
  are not persisted.

### Completed history boundary and transcript controls

These contracts keep completed runs, session-list responses, and browser-local presentation state
from overwriting newer or connection-specific state.

```ts
type CompletedRunOutcome = "final" | "aborted";

declare function resolveCompletedHistoryBoundary(
  current: ChatMessage[],
  loaded: ChatMessage[],
  currentMatches: ReadonlyMap<number, number>,
  completedRunId: string,
  outcome: CompletedRunOutcome,
): {
  loadedBoundary: number;
  completedAssistantAdopted: boolean;
  hasCompletedMatch: boolean;
  pageCoversCompletedRun: boolean;
};
```

`ChatMessage` is the client-owned message type in `state/types.ts`; the map relates current row
indexes to loaded row indexes. This is an internal client contract, not a plugin SDK export.

`resolveCompletedHistoryBoundary` accepts a terminal `outcome` of `"final"` or `"aborted"`. It
finds the last loaded row matched to the completed run. When there is no completed-run match, it
falls back to the loaded row matched to the user message that preceded that run's assistant turn.
If the completed assistant was not adopted, the outcomes diverge:

- For `"final"`, the resolver advances `loadedBoundary` through subsequent loaded rows until the
  next user turn. This admits the server's completed assistant output into the loaded boundary.
- For `"aborted"`, it stops at the existing `loadedBoundary` and does not scan forward. The merge
  therefore preserves the stopped text observed in local state instead of adopting a durable
  server suffix that was ahead of the stream when the abort landed.

```ts
const boundary = resolveCompletedHistoryBoundary(
  currentMessages,
  loadedMessages,
  currentMatches,
  completedRunId,
  "aborted",
);
```

An unmatched local assistant from another run is protected only when it occurs after the completed
run in the current transcript, or the completed run has no current boundary. This protects newer
live output from an older run's history reload without retaining an older stopped partial after a
subsequent run finishes and adopts the durable transcript.

`pageCoversCompletedRun` reports whether the loaded page actually reaches the completed run's
durable assistant row: true when the run's assistant output was adopted from the page, or when the
run's turn is anchored in the page (its preceding user row matched) and the rows after that anchor
reach an assistant row. A `final` page that ends at the run's user row — which is what the gateway
delivered before ADR 0089 made terminal events post-durable — does not cover it. When the outcome
is `final` and the page does not cover the run, `reconcileCompletedHistory` treats the streamed
assistant reply as still live instead of dropping it as already-represented; the next re-read whose
page contains the durable row replaces it through the ordinary entry and content matching. An
`aborted` run keeps the observed stopped text regardless, as above.

`SessionListRuntime` tags each request with a monotonically increasing `seq`. A response is applied
only while its captured `mySeq` equals the current sequence; otherwise it is silently dropped as
stale after a newer filter, search, sort, or page request. `dispose()` clears the pending 250 ms
search debounce and increments `seq`, preventing an in-flight Gateway response from landing on a
torn-down component. On `sessions.changed`, `refetchLoadedWindow()` starts at offset 0 and uses
`limit = Math.max(sessions.length, pageSize)`, preserving every page the user already loaded.

Navigation and transcript preferences are per connection:

- Navigation uses
  `openclaw.web.navigation:<encodedGatewayUrl>:<clientId>`, where the storage scope contains both
  `gatewayUrl` and `clientId`. Defaults are `assistantSort: "newest"`, `activityWindowHours: 4`,
  `includeInternal: false`, `chatSortBy: "updatedAt"`, `chatSortOrder: "desc"`,
  `selectedAgentId: null`, and `lastChatByAgent: {}`.
- Transcript display uses the `openclaw.web.transcript-display.v1` object, keyed within that object
  by `<gatewayUrl>|<clientId>`. Defaults are `showReasoning: false` and `tools: "minimum"`. A stored
  legacy `tools: "minimal"` preference loads as `"collapsed"`.

Display is not delivery. `showReasoning` and `tools: "hide" | "minimum" | "collapsed" | "full"` are
strictly browser-local presentation state in `DisplayMenu`; they do not alter Gateway execution or the
session's `reasoningLevel`. Tool detail strings render through the shared `shortenHomePaths` helper
(`src/agents/tool-display-common.ts`), which shortens absolute user-home paths to `~` (POSIX and
Windows) without Node-only APIs; both this app and the TUI `ui` package import it. Tool failures
remain visible even in `"hide"` mode:

```tsx
<div className="cl-tool-error" role="alert">
  {result.error}
</div>
```

A wholly hidden tool call renders `null`, so a tool-only assistant turn must not leave an empty
assistant bubble.

Web-client-specific footguns and their safe patterns:

- Do not apply a late session-list response after a filter or sort changes, or after unmount. Keep
  the `mySeq === seq` guard and invalidate the sequence in `dispose()`.
- Do not refetch only `pageSize` rows on `sessions.changed`; doing so drops an already loaded second
  or later page. Refetch the full loaded window from offset 0.
- Do not treat aborted and final reconciliation as equivalent. Advancing an aborted boundary can
  replace the exact stopped text the user saw with a durable suffix they never observed.
- Do not persist navigation or display preferences under an unscoped key. The same browser can
  connect to multiple gateways or client identities.
- Do not mutate the active row optimistically for model, thinking, reasoning, or label changes.
  Wait for the patch and refreshed session row; otherwise a refusal can leak one chat's pending
  state into another.
- Do not hide tool errors with ordinary tool details. Error output is an alert even when tool
  display is hidden.

```ts
// Do this: preserve the loaded window and invalidate work during teardown.
runtime.refetchLoadedWindow();
return () => runtime.dispose();
```

```ts
// Not this: a one-page refresh drops loaded rows, and an empty cleanup admits stale responses.
runtime.reload();
return () => {};
```

Contracts worth keeping when you change them:

- **Settings are not optimistic.** `ModelMenu`, `ThinkMenu` and the rename field patch the open chat
  through `WebClientRuntime.patchSession` and only ever show that chat's own row (`sessions.describe`,
  refreshed on every `sessions.changed` for it). A refused patch therefore needs no rollback:
  nothing on screen changed, and the control shows the gateway's message (`chat-controls-error`).
  "Assistant default" in the model menu sends `model: null`; Think sends `off`, `low`, `medium` or
  `high`; Send reasoning sends `reasoningLevel` `on` or `off`. `ThinkMenu` is inert (`aria-disabled`,
  a tooltip naming the model, no frame sent) when `models.list` reports `reasoning: false` for the
  chat's model.
- **Suggest never saves.** `rename-suggest` sends `sessions.title.prepare` with the chat's assistant
  id and the first user message currently loaded (its first 1000 characters), and only fills the
  field (60 characters at most). Enter or blur saves through `sessions.patch {label}`. A refusal, the
  rate limit or a `null` title shows `rename-error`.
- **Assistant picker.** `AssistantPicker` is opened by `sidebar-browse-assistants`. A pick sends
  exactly one `sessions.direct {agentId}` (a ref guard, not just React state, stops a double
  click); the gateway returns the caller's dmScope-correct direct session key (ADR 0109). There is
  no model select and no create step.
- **History and the chat leaf.** `useChatHistory` loads the newest page (`HISTORY_PAGE_SIZE`, 50)
  and pages older with the returned `cursor`. `WebClientRuntime` records the chat's leaf from its
  newest-page `chat.history` reads (the thinking reconcile opts out with `noteLeaf: false`); a
  `before` page never updates it. `LeafTracker` tells "never learned" (`undefined`: the send omits
  `expectedLeafEntryId`) from "known empty" (`null`: the send asserts an empty chat). After a
  final, aborted or error event for a run this client owns, `readLeafUntilStable` re-reads with
  `limit: 1` until two reads agree (every 25 ms, at most 40 attempts) and a send waits for it. A
  final for a run this client did not start never settles the leaf directly; it schedules a
  transcript re-read (`settleThenRefreshRows`), and that `foreign-turn` /
  `foreign-turn-preserve-local` page does note the leaf — only the own-run `completed-turn`
  reconcile opts out (`AppShell` sets `skipLeafNoteRef` for `completed-turn` alone) — so a client
  that has shown the other device's turn stops tripping the guard, while an unseen turn is still
  caught. Returning to a visible tab with a tracked leaf, an active chat and no own turn in flight
  reads the leaf once and emits `foreign-turn` when it moved. On a first `active-leaf-changed`
  refusal the send is still accepted (VAL-LEAF-002 reversal): the runtime re-learns the leaf
  (`refreshAfterUnseenChanges`), merges the unseen rows while keeping the optimistic user row
  (`foreign-turn-preserve-local`, no notice), and resends once automatically with a fresh
  `idempotencyKey` (`sendChatMessageOnce(params, "leaf-retry")`); switching chats while that
  refresh is in flight cancels the resend (`selectionSupersededError`) and the caller restores the
  draft. Only a second consecutive refusal takes the pre-reversal path —
  `recoverFromActiveLeafConflict`, the thread reload, `activeLeafConflict` (the
  `chat-changed-notice` banner) and `ActiveLeafChangedError`, whose draft restore `useChatSend`
  owns — so two back-to-back foreign appends cannot loop.
- **Steer and Queue.** While a reply streams, or a queued turn is still waiting, Enter or Send
  steers into the current turn via `sessions.steer` with `mode: "inject"` and `fallback: "queue"`
  (unless attachments are staged, which inject refuses, in which case it sends `mode: "queue"`).
  The send menu item "Send after reply" (`composer-send-menu-queue`) and desktop Ctrl/Cmd+Enter send
  `sessions.steer` with `mode: "queue"` and show the turn at once with `message-queued-badge`. Both
  send `fallback: "queue"`. Neither can carry a reply: the composer refuses both while a reply chip is set,
  because `sessions.steer` has no `replyToId`. On touch-primary devices (coarse pointer), plain Enter
  inserts a native newline, and Ctrl/Cmd+Enter runs the primary action (steer while streaming, queue
  with a staged file, send when idle) instead of queueing. A queued turn is saved in `sessionStorage`
  (`openclaw.web.pendingQueuedTurns.v1`, dropped after 24 hours) until its run drains, so it
  survives a reload or reconnect; `useChatHistory` shows it again only when `sessions.runs.list`
  still reports its run.
- **Replies.** Only a message with a real entry id (`__openclaw.id`) offers Reply. It sets the
  `replyChip` in the store (`composer-reply`, excerpt up to 140 characters), and the next `chat.send`
  carries its entry id as `replyToId` and clears the chip, whether or not the send succeeds. The
  quote renders from `__openclaw.replyTo` as `message-reply-quote`, live and after a reload.
- **Chat list.** `SessionListRuntime` owns the assistant filter, the search (debounced 250 ms),
  `loadMore` (the next `offset` is the number of rows already loaded) and the `sessions.changed`
  refetch, which re-reads offset 0 up to the rows already loaded so later pages are not dropped.
  Every request carries a sequence number and a superseded response is dropped. The open chat's own
  row is fetched separately, so the top bar stays live when a filter or search hides the chat from
  the list.
  Rows show the exact session key instead of a message preview; the client no longer requests
  unused last-message previews. `sessions.list` rows carry `internal: true` for internal sessions
  (cron, hook, heartbeat, subagent and acp keys), and the Sidebar groups those rows under an
  **Internal** label. They are hidden by default (`includeInternal: false`); the toggle includes
  them again.
  Gateway sorting precedes pagination; title sort uses labels before derived titles. Global title
  enrichment caps transcript reads at 16 at a time and yields between batches; normalized sort keys
  are computed once and are not returned. `includeDerivedTitles` remains opt-in: callers displaying
  the effective sorted titles should request it explicitly.
  `agentActivity` aggregates the newest eligible session timestamp before
  assistant, search, activity-window and pagination narrowing. The assistant list defaults to a
  4-hour window, pins the selected assistant, and refreshes its cutoff once per minute.
- **Assistant navigation.** Clicking an assistant scopes Sessions and restores its last explicitly
  selected eligible session, independently of the loaded page. Otherwise it opens the newest
  user-facing session or clears the runtime selection without creating one. Picking an assistant
  in the picker and first-send `sessions.direct` resolution keep the assistant selected too. Every
  actual activation invalidates older
  restoration callbacks, so delayed startup lookups cannot replace a newly created or selected chat.
  The selection is visible during lookup; the draft remains editable, but submission waits for
  lookup to finish or be superseded. Changing visibility only refilters a settled chat; an already
  pending assistant lookup restarts with the new eligibility rules. Creation revisions reject late
  creation replies. Separate send-navigation revisions invalidate leaf-gated sends on genuine
  navigation, but not on `All assistants`, the already-selected assistant, or the same open chat.
  `All assistants` explicitly clears the scope. Navigation preferences and remembered selections
  are scoped by gateway URL and client ID in browser storage; malformed remembered entries are discarded.
- **Display is not delivery.** `DisplayMenu` stores `showReasoning: false` and `tools: "minimum"`
  by default, separately from `reasoningLevel`. `extractTranscriptBlocks` preserves ordered text,
  thinking, tool calls, results and media; `Thread` pairs tools by call ID across loaded pages.
  Legacy `tool` roles and snake_case result metadata remain tools, not assistant prose.
  Hidden tool details retain errors, and wholly hidden execution turns leave no empty assistant
  row. Local final/aborted turns trigger a `completed-turn` reconciliation after the leaf settles,
  even while a newer local or queued run exists. The completed run ID and terminal outcome bound
  that snapshot: a final replaces its stale partial, while an aborted run keeps the observed stopped
  text rather than an ahead-of-stream durable suffix. `completed-history-boundary.ts` excludes newer
  assistant/execution data but admits matched newer durable users. Those rows keep their client IDs
  and run ownership; the queued marker clears on the runtime's start event, not on storage adoption.
  The merge retains newer partials, optimistic users, queued turns, older pages and errors without
  advancing the leaf guard. Legacy identity-less matches are one-to-one FIFO within durable-entry
  anchor intervals, so identical distinct turns remain distinct. Scoped loaded-history and
  older-page IDs distinguish replaceable heads from optimistic rows and preserve imported legacy
  entries. Superseded older-page responses cannot splice into a replacement load.
  Events received before `chat.send` acknowledges its run are buffered for exact attribution.
  A rejected send recovers the foreign question/reply through the non-destructive merge, including
  first-send-created chats, without deleting its own optimistic question or refusal. A durable foreign
  terminal event clears the fresh-empty-chat skip guard just like a local completion.
  Send failures belong to their original optimistic turn: an obsolete rejection cannot rewrite a
  newer chat or foreign reply. Distinct assistant message IDs remain distinct even with identical text.
  Media links and derived attachments share `normalizeMediaUrl`: HTTP(S) and inline raster
  images/WAV are allowed; unsupported schemes and data types remain non-interactive metadata.
- **Colours.** `ui/assistant-color.ts` maintains a browser-safe palette identical, in order, to
  `ASSISTANT_IDENTITY_COLORS` in
  `src/shared/assistant-identity-values.ts`. A configured `identity.color` wins; otherwise FNV-1a
  32-bit of the agent id modulo 8 picks one, so an unconfigured assistant keeps its colour across
  reloads and devices. The `--wai-assistant-<name>` and `-fg` tokens are in
  `packages/brand-tokens/tokens.css`; ADR 0084 section 6 records the contrast guarantee.
- **Menus.** `useDismissibleMenu` closes a menu on an outside mousedown and on Escape, returning
  focus to its trigger. `ModelMenu`, `ThinkMenu` and the Composer send menu all use it; do not copy
  its body into a new menu.

## Dictate and Voice

Dictate and Voice mode are Composer controls (test ids `composer-dictate` and `composer-voice`),
not phase placeholders. When `talk.catalog` does not offer a control it renders through
`DisabledControl` with `reason="unavailable on this gateway"`; when it is offered it is a real
toggle button: `aria-pressed` plus the `cl-composer-btn--active` style while it is on
(`recording` for Dictate; `listening`, `thinking` or `speaking` for Voice mode), and a
`data-dictate-status` / `data-voice-status` attribute mirroring the hook state — the `error` value
gets the danger outline from `client.css`, and the next click retries. `features.voice` is
ignored.

Availability comes from `talk.catalog`, and updates on reconnect:

- Dictate is live when `conversationEnabled` is true and `streamingTranscription` has a
  `configured: true` row.
- Voice follows `conversationEngine`. With `"stt-tts"` (the default, also used when the field is
  absent) Voice is live only when Dictate's conditions hold and `speech` also has a configured row.
  With `"realtime"` Voice is live when `conversationEnabled` is true and `realtime.activeProvider`
  is not null; `talk.session.create` then sends `mode: "realtime"` and capture runs at the
  result's `inputSampleRateHz` (24 kHz).

`useDictate` returns `status` `unavailable | idle | recording | transcribing | error`, a live cumulative
`transcript` while recording, `commit: { text: string; nonce: number } | null`, `consumeCommit(): void`,
and `errorMessage` (mic denied or no input device). The live transcript previews in the textarea as a
read-only draft with an accent border and muted text (`.cl-composer--dictating`), without breaking the
textarea height cap. When dictation stops or encounters a capture error, `commit` receives the final or
last-captured transcript and commits into the draft at the caret position via `insertDictation`; the composer
calls `onDictateCommitConsumed` to clear the commit.

`useVoice` returns `status` `unavailable | idle | listening | thinking | speaking | error` and
`captions: { user, assistant }`. Voice does not fill the composer. Toggle starts or stops the
session; `thinking` counts as on. A start rejection is swallowed here; the seam's `error` status
is what the button shows.

While Voice is `listening`, `thinking` or `speaking`, the Composer renders `VoiceCaptions`
(`ui/VoiceCaptions.tsx`, `data-testid="voice-captions"`, `aria-live="polite"`) above the input
row: an orb `cl-voice-orb` with a `--listening`, `--thinking` or `--speaking` modifier (its pulse
stops under `prefers-reduced-motion`), the status label, and two caption lines,
`cl-voice-caption--user` and `cl-voice-caption--assistant`. The caption region
(`cl-voice-captions__scroll`) is height-capped at `min(45vh, 18rem)` and scrolls instead of
growing the composer; its `column-reverse` layout pins the scroll origin to the newest line, so
an active conversation stays in view without yanking a reader who scrolled up. The user caption
is replaced by each
`transcript.delta`/`transcript.done`; the assistant caption is cleared on `turn.started` and
appended from `output.text.delta` (cascaded deltas are trimmed clauses joined with a single
space; realtime deltas are raw increments concatenated verbatim). `tool.call` sets `thinking`. On
`transcript.persisted` the
runtime re-reads the active chat, so the persisted turns appear in the thread without a reload.

While either feature is live, switching chats is locked. The runtime derives the lock
synchronously from the live talk seams (`navigationLockReason`: a dictate take from its first
toggle click, including the lazy create of a first chat, until its stop settles, whether the
stop succeeds, fails, or the gateway drops; a Voice conversation while `listening` or
`speaking` (or `thinking`); dictation wins when both are live), so a guard holds in the same tick the feature
starts — no React effect latency. A user-initiated switch — a `sidebar-session` row, the unread
bell, an assistant chip or the assistant picker — is then refused: no session change and no
`sessions.direct`/history traffic, plus a `role="alert"` notice (`chat-switch-blocked`) saying
exactly what to stop: "Stop dictation to switch chats." or "Turn off voice to switch chats.".
The runtime emits `onNavigationBlocked` for every refusal and `onNavigationLockChanged` when the
lock changes; the notice's reason follows the lock (a dictation→voice handoff re-labels it), and
it clears when the runtime lock clears. A `sessions.direct`
response that lands after the lock leaves the resolved row unselected in the sidebar
instead of switching. The lock only gates user intent: startup restore (`forceSwitchSession`),
send-create of a first message, and a chat deleted elsewhere still switch — a live Voice
conversation is stopped cleanly when its chat is deleted elsewhere, while a Dictation take
(session-independent) keeps running and commits into the draft. An assistant lookup that settles
while locked just releases the pending navigation without touching the open thread.

Playback and barge-in come from the `talk-client` package (`createTalkAudioPlayback`,
`createBargeInDetector`), not from `wednesdayai/plugin-sdk`. Call playback with `preRollMs: 40`
and `echoSafeSink: true` for Voice. Both options default off (`preRollMs` 0, `echoSafeSink` false),
which is what the operator console keeps. `preRollMs` delays only the first chunk of a fresh burst.
`echoSafeSink` routes through a `MediaStreamAudioDestinationNode`
into an `<audio>` element so echo cancellation has a real media element.

The barge-in detector stays disarmed except while `kind: "speech"` audio is playing. Do not arm it
for `filler` or `ack`. Re-arm it on `output.audio.resumed` while speech is still active, and do
not disarm it in the gap between speech chunks. Voice uses a 150 ms minimum burst (the package
default is 250 ms) at the package's −45 dBFS threshold. On detection, pause playback locally
before `talk.session.bargeIn`. Those two timestamps are `performance.now()`. Speech
`talk.session.mark` timestamps are played-audio milliseconds on the turn timeline (0 at the first
speech sample), attached when the chunk is enqueued, not at `turn.ended`. Realtime sessions
differ: attach the mark once, at `output.audio.done`, and acknowledge with a session-monotonic
timestamp that never decreases — per-turn offsets would drop every ack after the first
(shorter) reply.

If the gateway socket drops, stop the microphone immediately and return Voice to `idle`, including
when the drop happens while start is still in flight. Do not wait on `talk.session.close`: that
RPC blocks until the socket is ready again. Dictate stops capture the same way, without waiting
for a transcript that can no longer arrive.

Frame shapes are in [Talk sessions](/gateway/protocol#talk-sessions).

## Read aloud

The Read aloud action on assistant messages speaks that reply through the gateway's per-agent TTS
config (`messages.tts` merged with `agents.list[].tts`; ADR 0102, wire shapes in
[TTS read aloud](/gateway/protocol#tts-read-aloud)). `app/use-read-aloud.ts`
owns the state: one `tts.readAloud.status` read per runtime, agent and connection, one shared
`ReadAloudPlayer`, and a `ReadAloudControls {unavailableReason, activeKey, phase, error, toggle}`
value. `AssistantMessage` takes it as `readAloud` plus `readAloudKey` (a stable key per message,
`String(message.id ?? message.entryId ?? idx:<index>)` from `Thread`).

`unavailableReason` is first match wins: `unavailable while offline` when disconnected,
`unavailable during Voice mode`, `unavailable on this gateway` when the status reports
`enabled: false`. A failed status read gates the control off instead of guessing the feature is
live, and only a status for the current agent counts. When the player reports a
`read_aloud_disabled` refusal, the hook bumps its status revision so the gate re-reads instead of
staying stale. Playback stops when the session changes, Voice mode engages, or the connection
drops.

`providers/read-aloud-text.ts` turns the reply into speech chunks:

- `messageMarkdownForSpeech` prefers the message transcript's `text` blocks over the streamed
  content.
- `extractSpeakableUnits` parses the markdown with remark (GFM) and keeps one unit per paragraph,
  heading and list item, recursing into blockquotes, while dropping code blocks, inline and block
  html, tables, rules and metadata nodes. Unpunctuated units get a trailing period so the voice
  pauses at the unit end.
- `packSpeechChunks` joins units with blank lines under the gateway's `maxTextLength`, splitting an
  oversized unit on sentence boundaries (`Intl.Segmenter`), then on whitespace. Every chunk is
  1..max characters and no non-whitespace text is lost.

`providers/read-aloud-player.ts` is the framework-free playback engine. `start` runs synchronously
inside the click handler — it creates and resumes the shared `AudioContext` there, which unlocks
Safari/iOS playback from the user gesture — then fetches chunk 0 and prefetches the next chunk
while the current one plays, with at most one `tts.speak` request in flight. A generation counter
makes `stop()`, or starting another message, retire in-flight work silently: a late synth promise
never surfaces audio or errors. `describeReadAloudError` maps a `read_aloud_disabled` refusal to
`Read aloud is turned off for this assistant.`, any other gateway error to
`Couldn't read aloud: <message>`, and a `decodeAudioData` failure to
`Couldn't play the audio in this browser.`

Markup contract:

- The live button carries `data-testid="message-read-aloud"`, `aria-label` and `title`
  `Read aloud` / `Stop reading` while active, `aria-pressed`, `aria-busy` while loading, and
  `data-read-aloud-phase` set to `loading` or `playing` while this message reads, `idle`
  otherwise.
- The actions row gets `data-reading="true"` while this message reads or shows an error.
- An error renders a `role="status"` span with `data-testid="message-read-aloud-error"`.

## Busy state, unread badges and reply notifications

Three layers, kept separate: the runs projection says which chats have a run in flight, the store
carries the unread chat keys the sidebar renders, and `use-reply-notifications` owns the
per-device unread state and turns hidden-tab replies into optional desktop notifications.

### Busy state

- `selectBusySessionKeys(rows)` (`runs/runs-model.ts`) maps the `sessions.runs.list` projection
  the sidebar and Runs panel already read to the session keys with a run in flight: rows whose
  `groupForSessionRunStatus(status)` is `queued` or `running`, excluding `kind === "heartbeat"`
  (heartbeat output is suppressed in chat; counting it would pulse the busy state on every tick).
- `useBusySessionKeys(controller)` (`app/use-busy-sessions.ts`) reads the projection with
  `useSyncExternalStore` and holds a `useRunsLease`, so it stays live while the shell is mounted
  even when the Sidebar is not.
- `AppShell` ORs the open chat's key into the composer's streaming state, so Stop sends
  `chat.abort { sessionKey }` and Enter steers via `sessions.steer` for a run this client never
  started — one running in the same chat from another device, or one that predates a reload.
- `ui/TypingIndicator.tsx` is the three-dot indicator: `role="status"` with
  `aria-label="<assistant> is working"`, the dots `aria-hidden`. `Thread` shows it while its
  `isBusy` prop is true (not only before the first streamed text) and sets `aria-busy` on the
  thread element; `EmptyState` shows it while a still-empty chat's first turn runs elsewhere. The
  sidebar marks busy chats with `sidebar-session-busy` (a pulsing `cl-sb-busy` dot,
  `role="img"`, `aria-label="Working"`); both pulses are disabled under `prefers-reduced-motion`.

### Unread badges and the title count

- The runtime broadcasts `assistantReply { sessionKey, runId, text, at }` on its events bus for a
  `chat` `final` that carries non-empty assistant text, once per `runId` (bounded FIFO of 200 run
  ids), from `handleEvent` before `handleChatEvent` — so a pre-ack buffered final replayed after
  the send acknowledgement still fires exactly once. Heartbeat finals (`message: undefined`),
  silent finals and user-role finals never fire. `at` is the gateway-stamped `message.timestamp`
  of the final, or `null` from a gateway that does not stamp timestamps; unread detection is then
  live-only.
- `AppShell`'s `useReplyNotifications` owns unread state per browser or installed app: a chat is
  unread when an assistant reply arrived after this device last had the chat open. Detection is
  durable — it compares the session row's `lastReplyAt` (see
  [Gateway protocol](/gateway/protocol#sessions-list-sorting-agent-activity-and-visibility))
  against a per-device read cursor, and the state survives a reload. It publishes the unread keys
  to the store (`setUnreadSessions` on `unreadBySession`, rendered as the static
  `sidebar-session-unread` dot, `aria-label="New reply"`) and clears a chat when it is activated,
  when the tab becomes visible with it open, or through the top-bar bell's **Mark all as read**.
  The document title gets a `(N)` prefix counting unread chats against the title captured at
  mount. Badges and the count run whether or not the notification opt-in is on.
- `providers/unread-state.ts` is the pure state machine behind that durability (`UNREAD_STATE_STORAGE_KEY`
  is `openclaw.web.unread.v1`, scoped like every other preference): per chat a seen floor and an
  unread timestamp, a baseline seeded from the first attention window (replies older than it never
  light), an optional read-all timestamp, a monotonic cross-tab merge in which a read always beats
  an unread of the same or older reply, and pruning that sheds the oldest seen entries past 2000
  keys by raising the baseline. Timestamps only — never message text or titles. A chat deleted
  elsewhere is dropped by tombstoning it seen and forgetting the key, both from the live
  `sessionDeleted` event and from a completed read (`completeAt`) whose window no longer lists it.
- `providers/attention-runtime.ts` is the attention window the unread owner reconciles against.
  In the default Sessions view it adopts the sidebar's own completed page (`SESSIONS_LIST_LIMIT`, 100
  rows); anywhere else `refresh()` reads the newest `ATTENTION_LIST_LIMIT` (50) user-facing chats
  with `includeDerivedTitles`, coalescing to one fetch in flight plus one trailing and never
  emitting on failure. The runtime publishes `attentionRows { sessions, completeAt }`; `completeAt`
  is the response `ts` only when the read returned the whole window (`hasMore: false`), so only a
  complete window can clear chats that vanished from it. A hidden-to-visible resume refetches the
  sidebar and attention windows at most once per `RESUME_REFRESH_MIN_MS` (10 s).
- `ui/AttentionMenu.tsx` renders the bell: an icon trigger whose badge caps at `99+`
  (`aria-label="Notifications, N unread"`) opening a dismissible menu that lists unread chats
  (assistant colour marker, chat name, an assistant and recency line) and offers
  **Mark all as read** only when the list is non-empty; an empty menu reads "You're all caught
  up".
- Operator decision: nothing from the reply itself may reach the OS. `AssistantReply.text` exists
  only so empty finals can be skipped — never render it in a notification, a tooltip or a title.

### Desktop notifications (opt-in)

- `providers/reply-notifications.ts` owns the browser seam: `notificationSupport()` (returns
  `"unsupported"` when there is no `Notification` constructor, else the live permission), the
  scoped opt-in flag under `openclaw.web.notifications.v1` keyed `${gatewayUrl}|${clientId}`
  (the same per-connection scoping rule as the theme and display preferences),
  `formatUnreadTitle(base, total)`, and `showReplyNotification`.
- A notification is shown only while the tab is hidden, the opt-in is on and permission is
  `granted`. Its title is `<assistant name> replied` (the chat's agent name when it resolves, else
  the configured assistant name), its body is the chat's title, and `tag` is the session key, so a
  newer reply replaces the older notification for that chat. `showReplyNotification` returns
  `false` when the constructor throws (Android Chrome and iOS throw without a service worker); the
  caller then records `unsupported` so the account menu stops offering the toggle.
- `AccountMenu` renders the Notifications radiogroup (`account-menu-notifications-off|on`).
  `Notification.requestPermission()` runs inside the click handler — it requires a user gesture.
  A `denied` result keeps the toggle Off and shows `Blocked in browser settings`; an
  `unsupported` browser renders a `DisabledControl` with
  `reason="Not supported in this browser"`.

```ts
// Do this: the event carries only what the badge needs; the text never leaves the client.
runtime.onAssistantReply(({ sessionKey }) => markUnread(sessionKey));

// Not this: reply text in an OS notification surface.
new Notification(`${name} replied`, { body: reply.text });
```

## Stay inside the ADR 0077 allowlist

The client connects with only `operator.sessions.read` and `operator.sessions.write`, and the
gateway admits a fixed method and event set for them (listed under
[narrow scope method allowlist](/gateway/protocol#narrow-scope-method-allowlist) and
[event allowlist](/gateway/protocol#narrow-scope-event-allowlist); ADR 0077 records the decision; the
sources of truth are `NARROW_SESSION_READ_METHODS` and `NARROW_SESSION_WRITE_METHODS` in
`src/gateway/method-scopes.ts` and `NARROW_SESSION_EVENT_ALLOWLIST` in
`src/gateway/server-broadcast.ts`).

- Methods: reads such as `agents.list`, `sessions.list`, `chat.history`, `sessions.runs.*`,
  `tasks.runs.*`, `talk.catalog`, and `tts.readAloud.status`; writes `chat.send`, `chat.abort`,
  `sessions.create`, `sessions.steer`, `sessions.abort`, `sessions.runs.cancel`,
  `sessions.runs.continue`, `sessions.patch`, `sessions.title.prepare` (ADR 0083),
  `talk.session.create`, `talk.session.appendAudio`, `talk.session.close`,
  `talk.session.cancelTurn`, `talk.session.mark`, `talk.session.bargeIn` (ADR 0086), and
  `tts.speak` (ADR 0102). `sessions.patch` is field-guarded even for this narrow
  client: only `label`, `model`, `thinkingLevel` and `reasoningLevel` are admitted
  (`NARROW_SESSION_PATCH_FIELDS`); every other field still needs `operator.admin` and is refused
  with `missing scope: operator.admin`, the same shape as a fully unlisted method. The patch
  response is redacted for this client (no `path`, none of the admin-only entry fields), so never
  read those from a patch result.
- Events: `chat`, `sessions.changed`, `runs.invalidated`, `talk.event` (this connection's own Talk
  sessions only), `tick`, `heartbeat`.
- Not admitted: `talk.realtime.*`, `talk.config`, `talk.mode`, `talk.metrics`, `config.*`,
  `logs.*`, `cron.*`, `node.*`, `send`, and anything not listed. A method outside the list is
  refused by the gateway, so a feature that needs one is an ADR amendment, not a client-only
  change.

Before you add an RPC call, check it against the list. The brand e2e records every frame the
browser sends and fails if one is outside the allowlist, which catches a stray call even when a
unit test with a mocked runtime passes.

## Test at the real entry point

Unit tests under `apps/web/src/**` (`pnpm test:web`) prove components in jsdom. They cannot see
scrolling, fonts, `color-scheme` or gateway frames. For a behaviour change, also drive the built
bundle in real Chromium against a real gateway using the harness in
`test/helpers/user-client-web-harness.ts`; see
[Testing](/help/testing#web-client-and-brand-e2e-suites) for the suites and their caveats.
