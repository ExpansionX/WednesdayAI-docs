# Channel troubleshooting

Use this page when a channel connects but behavior is wrong.

## Command ladder

Run these in order first:

```bash
wednesdayai status
wednesdayai gateway status
wednesdayai logs --follow
wednesdayai doctor
wednesdayai channels status --probe
```

Healthy baseline:

- `Runtime: running`
- `RPC probe: ok`
- Channel probe shows connected/ready

## WhatsApp

### WhatsApp failure signatures

| Symptom                         | Fastest check                                       | Fix                                                     |
| ------------------------------- | --------------------------------------------------- | ------------------------------------------------------- |
| Connected but no DM replies     | `wednesdayai pairing list whatsapp`                 | Approve sender or switch DM policy/allowlist.           |
| Group messages ignored          | Check `requireMention` + mention patterns in config | Mention the bot or relax mention policy for that group. |
| Random disconnect/relogin loops | `wednesdayai channels status --probe` + logs        | Re-login and verify credentials directory is healthy.   |

Full troubleshooting: [/channels/whatsapp#troubleshooting](/next/admin/channels/whatsapp#troubleshooting)

## Telegram

### Telegram failure signatures

| Symptom                                | Fastest check                                                   | Fix                                                                                                                                 |
| -------------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `/start` but no usable reply flow      | `wednesdayai pairing list telegram`                             | Approve pairing or change DM policy.                                                                                                |
| Bot online but group stays silent      | Verify mention requirement and bot privacy mode                 | Disable privacy mode for group visibility or mention bot.                                                                           |
| Repeated `getUpdates` network retries  | Channels UI Telegram account card + `wednesdayai logs --follow` | Fix DNS/IPv6/proxy routing to `api.telegram.org`; recovery backoff is automatic.                                                    |
| `deleteWebhook failed` at startup      | `wednesdayai logs --follow` for `succeeded after N attempts`    | A success line means cleanup recovered. Otherwise troubleshoot routing for transport errors or fix the reported Telegram API error. |
| Telegram account state is `conflicted` | Channels UI `mode`/`state`/`owner` + account config             | Ensure each enabled account resolves to a distinct bot token and only one gateway owns each token.                                  |
| Webhook account rejects or times out   | Channels UI webhook receipt, pending updates, and logs          | Verify public `webhookUrl`, secret token, reverse proxy, listener path, and endpoint response time.                                 |
| Send failures with network errors      | Inspect logs for Telegram API call failures                     | Fix Bot API egress, proxy, or flood-wait handling; check delivery retry fields in Channels UI.                                      |
| Upgraded and allowlist blocks you      | `wednesdayai security audit` and config allowlists              | Run `wednesdayai doctor --fix` or replace `@username` with numeric sender IDs.                                                      |

Full troubleshooting: [/channels/telegram#troubleshooting](/next/admin/channels/telegram#troubleshooting)

## Discord

## iMessage and BlueBubbles

### iMessage and BlueBubbles failure signatures

| Symptom                          | Fastest check                                                                 | Fix                                                   |
| -------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------- |
| No inbound events                | Verify webhook/server reachability and app permissions                        | Fix webhook URL or BlueBubbles server state.          |
| Can send but no receive on macOS | Check macOS privacy permissions for Messages automation                       | Re-grant TCC permissions and restart channel process. |
| DM sender blocked                | `wednesdayai pairing list imessage` or `wednesdayai pairing list bluebubbles` | Approve pairing or update allowlist.                  |

Full troubleshooting:
