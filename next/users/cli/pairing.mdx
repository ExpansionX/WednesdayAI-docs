# `wednesdayai pairing`

Approve or inspect DM pairing requests (for channels that support pairing).

Related:

- Pairing flow: [Pairing](/next/admin/channels/pairing)

## Commands

```bash
wednesdayai pairing list telegram
wednesdayai pairing list --channel telegram --account work
wednesdayai pairing list telegram --json

wednesdayai pairing approve telegram <code>
wednesdayai pairing approve telegram <code> --identity Alice
wednesdayai pairing approve --channel telegram --account work <code> --notify
```

## Notes

- Channel input: pass it positionally (`pairing list telegram`) or with `--channel <channel>`.
- `pairing list` supports `--account <accountId>` for multi-account channels.
- `pairing approve` supports `--account <accountId>` and `--notify`.
- `pairing approve --identity <name>` links the approved sender (`<channel>:<id>`) to that identity
  after approval. The identity is resolved before the one-time code is consumed, so a typo never
  burns the code; an unknown name fails with
  `Unknown identity "<name>". Known identities: …`. If the link write fails, the approval stands
  and the command prints the exact follow-up:
  `Approved, but linking failed: <reason>. Link it with: wednesdayai identity link <name> <channel>:<id>`.
  See [Identities](/next/admin/gateway/identity).
- If only one pairing-capable channel is configured, `pairing approve <code>` is allowed.
