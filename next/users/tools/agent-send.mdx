# `wednesdayai agent` (direct agent runs)

`wednesdayai agent` runs a single agent turn without needing an inbound chat message.
By default it goes **through the Gateway**; add `--local` to force the embedded
runtime on the current machine.

## Behavior

- Required: `--message <text>`
- Session selection:
  - `--session-id <id>` reuses an existing session by id (it wins over `--agent` and `--to`; with `--agent`, the session must belong to that agent), **or**
  - through the Gateway, with no `--session-id`, the turn runs in your own per-pair conversation on the chosen agent (`--agent <id>`, else the default agent): the key `sessions.direct` resolves for this device/person. A direct `--to` is the delivery target only; a group/channel `--to` target still selects its own session, and a `session.scope: "global"` install uses its shared `global` session.
  - The system main session (`agent:<agentId>:<mainKey>`) is never a chat destination (#2824). An embedded run (`--local`, or the fallback when the Gateway request fails) has no device identity: without `--session-id`, a turn that would land on main is refused with an error naming `--session-id`. A `session.scope: "global"` install keeps its earlier selection on every path: `--agent` and a direct `--to` use the shared `global` session.
- Runs the same embedded agent runtime as normal inbound replies.
- Thinking/verbose flags persist into the session store.
- Output:
  - default: prints reply text (plus `MEDIA:<url>` lines)
  - `--json`: prints structured payload + metadata
- Optional delivery back to a channel with `--deliver` + `--channel` (target formats match `wednesdayai message --target`).
- Use `--reply-channel`/`--reply-to`/`--reply-account` to override delivery without changing the session.

If the Gateway is unreachable, the CLI **falls back** to the embedded local run.

## Examples

```bash
wednesdayai agent --to +15555550123 --message "status update"
wednesdayai agent --agent ops --message "Summarize logs"
wednesdayai agent --session-id 1234 --message "Summarize inbox" --thinking medium
wednesdayai agent --to +15555550123 --message "Trace logs" --verbose on --json
wednesdayai agent --to +15555550123 --message "Summon reply" --deliver
wednesdayai agent --agent ops --message "Generate report" --deliver --reply-channel slack --reply-to "#reports"
```

## Flags

- `--local`: run locally (requires model provider API keys in your shell)
- `--deliver`: send the reply to the chosen channel
- `--channel`: delivery channel (`whatsapp|telegram|discord|googlechat|slack|signal|imessage`, default: `whatsapp`)
- `--reply-to`: delivery target override
- `--reply-channel`: delivery channel override
- `--reply-account`: delivery account id override
- `--thinking <off|minimal|low|medium|high|xhigh>`: persist thinking level (GPT-5.2 + Codex models only)
- `--verbose <on|full|off>`: persist verbose level
- `--timeout <seconds>`: override agent timeout
- `--json`: output structured JSON
