# `wednesdayai config`

Config helpers: get/set/unset/validate values by path and print the active
config file. Run without a subcommand to open
the configure wizard (same as `wednesdayai configure`).

## Examples

```bash
wednesdayai config file
wednesdayai config get browser.executablePath
wednesdayai config set browser.executablePath "/usr/bin/google-chrome"
wednesdayai config set agents.defaults.heartbeat.every "2h"
wednesdayai config set agents.list[0].tools.exec.node "node-id-or-name"
wednesdayai config unset tools.web.search.apiKey
wednesdayai config validate
wednesdayai config validate --json
```

## Paths

Paths use dot or bracket notation:

```bash
wednesdayai config get agents.defaults.workspace
wednesdayai config get agents.list[0].id
```

Use the agent list index to target a specific agent:

```bash
wednesdayai config get agents.list
wednesdayai config set agents.list[1].tools.exec.node "node-id-or-name"
```

## Values

Values are parsed as JSON5 when possible; otherwise they are treated as strings.
Use `--strict-json` to require JSON5 parsing. `--json` remains supported as a legacy alias.

```bash
wednesdayai config set agents.defaults.heartbeat.every "0m"
wednesdayai config set gateway.port 19001 --strict-json
wednesdayai config set channels.whatsapp.groups '["*"]' --strict-json
```

## Subcommands

- `config file`: Print the active config file path (resolved from `OPENCLAW_CONFIG_PATH` or default location).

Restart the gateway after edits.

`config unset` of a single top-level key (for example `channels`) names that key so the write guard allows the removal. A gateway `config.set` / `config.apply` / `config.patch` that drops a top-level key without `allowTopLevelKeyRemoval` is refused. See [Config writes](/admin/gateway/config-writes).

## Validate

Validate the current config against the active schema without starting the
gateway.

```bash
wednesdayai config validate
wednesdayai config validate --json
```
