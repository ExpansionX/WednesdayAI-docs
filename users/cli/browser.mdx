# `wednesdayai browser`

Manage WednesdayAI's browser control server and run browser actions (tabs, snapshots, screenshots, navigation, clicks, typing).

Related:

- Browser tool + API: [Browser tool](/users/tools/browser)
- Chrome extension relay: [Chrome extension](/users/tools/chrome-extension)

## Common flags

- `--url <gatewayWsUrl>`: Gateway WebSocket URL (defaults to config).
- `--token <token>`: Gateway token (if required).
- `--timeout <ms>`: request timeout (ms).
- `--browser-profile <name>`: choose a browser profile (default from config).
- `--json`: machine-readable output (where supported).

## Quick start (local)

```bash
wednesdayai browser --browser-profile chrome tabs
wednesdayai browser --browser-profile openclaw start
wednesdayai browser --browser-profile openclaw open https://example.com
wednesdayai browser --browser-profile openclaw snapshot
```

## Profiles

Profiles are named browser routing configs. In practice:

- `openclaw`: launches/attaches to a dedicated WednesdayAI-managed Chrome instance (isolated user data dir).
- `chrome`: controls your existing Chrome tab(s) via the Chrome extension relay.

```bash
wednesdayai browser profiles
wednesdayai browser create-profile --name work --color "#FF5A36"
wednesdayai browser delete-profile --name work
```

Use a specific profile:

```bash
wednesdayai browser --browser-profile work tabs
```

## Tabs

```bash
wednesdayai browser tabs
wednesdayai browser open https://docs.wednesdayai.dev
wednesdayai browser focus <targetId>
wednesdayai browser close <targetId>
```

## Snapshot / screenshot / actions

Snapshot:

```bash
wednesdayai browser snapshot
```

Screenshot:

```bash
wednesdayai browser screenshot
```

Navigate/click/type (ref-based UI automation):

```bash
wednesdayai browser navigate https://example.com
wednesdayai browser click <ref>
wednesdayai browser type <ref> "hello"
```

## Chrome extension relay (attach via toolbar button)

This mode lets the agent control an existing Chrome tab that you attach manually (it does not auto-attach).

Install the unpacked extension to a stable path:

```bash
wednesdayai browser extension install
wednesdayai browser extension path
```

Then Chrome → `chrome://extensions` → enable "Developer mode" → "Load unpacked" → select the printed folder.

### Pairing

Generate a pairing string for the extension:

```bash
# Local (same machine)
wednesdayai browser extension pair

# Remote (gateway on another machine)
wednesdayai browser extension pair --gateway-url wss://gateway-host:18789

# JSON output
wednesdayai browser extension pair --json
wednesdayai browser extension pair --gateway-url wss://gateway-host:18789 --json
```

The `--gateway-url` flag accepts a `wss://` (or `ws://` for loopback) URL. If no path is given, `/browser/extension` is used. The path must be exactly `/browser/extension` — prefixed paths are rejected.

Paste the printed pairing string into the extension popup's pairing field.

Full guide: [Chrome extension](/users/tools/chrome-extension)

## Remote browser control (node host proxy)

If the Gateway runs on a different machine than the browser, run a **node host** on the machine that has Chrome/Brave/Edge/Chromium. The Gateway will proxy browser actions to that node (no separate browser control server required).

Use `gateway.nodes.browser.mode` to control auto-routing and `gateway.nodes.browser.node` to pin a specific node if multiple are connected.

Security + remote setup: [Browser tool](/users/tools/browser), [Remote access](/admin/gateway/remote), [Tailscale](/admin/gateway/tailscale), [Security](/admin/gateway/security)
