# `openclaw devices`

Manage device pairing requests and device-scoped tokens.

## Commands

### `openclaw devices list`

List pending pairing requests and paired devices.

```
openclaw devices list
openclaw devices list --json
```

`--json` returns `pending` and `paired` arrays; each `paired` entry carries a `deviceId` and, when
the device is linked to a person, an `identity` field holding the `session.identityLinks` key.
Gateway clients (web client, Control UI) send their turns as `device:<deviceId>`, and assistants
with [workspace lanes](/concepts/workspace-lanes#linking-gateway-devices) require that value in the
person's `session.identityLinks` entry. The paired-device table also shows an `Identity` column
with the linked key.

### `openclaw devices link <deviceId> --identity <key>`

Link a paired device to a `session.identityLinks` identity (see #981's operator path, ADR 0104).
The key must already exist; unknown keys are never created:

```
openclaw devices link <deviceId> --identity Alice
openclaw devices link <deviceId> --identity Alice --json
```

Prints `Linked <deviceId> to <Identity>.`; when the device is already linked to that identity it
prints `<deviceId> is already linked to <Identity>.` and writes nothing. A device belongs to one
person: linking moves the `device:<deviceId>` value from any other key to the target. The
identities `prototype`, `constructor` and `__proto__` are reserved and refused; rename them in
`session.identityLinks` first.

### `openclaw devices unlink <deviceId>`

Remove the device's `device:<deviceId>` value from every `session.identityLinks` key:

```
openclaw devices unlink <deviceId>
openclaw devices unlink <deviceId> --json
```

Prints `Unlinked <deviceId> from <keys>.`, or `<deviceId> is not linked.` The running gateway's
live config is updated even when the config file already had no link.

### `openclaw devices remove <deviceId>`

Remove one paired device entry. If the device was linked, the removal also unlinks it and prints
`Unlinked from <keys>.`

```
openclaw devices remove <deviceId>
openclaw devices remove <deviceId> --json
```

### `openclaw devices clear --yes [--pending]`

Clear paired devices in bulk.

```
openclaw devices clear --yes
openclaw devices clear --yes --pending
openclaw devices clear --yes --pending --json
```

### `openclaw devices approve [requestId] [--latest]`

Approve a pending device pairing request. If `requestId` is omitted, OpenClaw
automatically approves the most recent pending request.

```
openclaw devices approve
openclaw devices approve <requestId>
openclaw devices approve --latest
```

### `openclaw devices reject <requestId>`

Reject a pending device pairing request.

```
openclaw devices reject <requestId>
```

### `openclaw devices rotate --device <id> --role <role> [--scope <scope...>]`

Rotate a device token for a specific role (optionally updating scopes).

```
openclaw devices rotate --device <deviceId> --role operator --scope operator.read --scope operator.write
```

### `openclaw devices revoke --device <id> --role <role>`

Revoke a device token for a specific role.

```
openclaw devices revoke --device <deviceId> --role node
```

## Common options

- `--url <url>`: Gateway WebSocket URL (defaults to `gateway.remote.url` when configured).
- `--token <token>`: Gateway token (if required).
- `--password <password>`: Gateway password (password auth).
- `--timeout <ms>`: RPC timeout.
- `--json`: JSON output (recommended for scripting).

Note: when you set `--url`, the CLI does not fall back to config or environment credentials.
Pass `--token` or `--password` explicitly. Missing explicit credentials is an error.

## Notes

- Token rotation returns a new token (sensitive). Treat it like a secret.
- The pairing and token commands (`list`/`approve`/`reject`/`remove`/`clear`/`rotate`/`revoke`) require `operator.pairing` (or `operator.admin`) scope. `devices link` and `devices unlink` require `operator.admin`: linking grants a person's identity.
- `devices clear` is intentionally gated by `--yes`.
- If pairing scope is unavailable on local loopback (and no explicit `--url` is passed), list/approve can use a local pairing fallback.
- Successful bootstrap redemptions (including the bounded-profile ids `openclaw-even-g2-node`, `openclaw-mentra-node`, `openclaw-user-client`) are approved silently and appear under `paired`; non-bootstrap pairing and role or scope upgrade requests can still appear under `pending`. To cut a device off, `devices revoke --device <id> --role <role>` prevents subsequent reconnects but does not close an existing connection: restart the gateway (or otherwise close its socket) for immediate containment. `devices remove <id>` deletes the row so the device must scan a new setup code (see [MentraOS glasses](/platforms/mentra-glass)).
